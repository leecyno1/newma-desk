# 个股事件与资金合同

## 定位

`instock-event-flow` 是 evidence-first 的事件与资金工作台。它既可按 A 股代码读取 Desk 已托管数据，也保留 Newma Agent 点时事件包输入；项目负责确定性去重、时效、来源覆盖、异常强度、方向和证券归并。

## 接口

页面历史恢复：代码查询结果恢复自身证券与截止日，后续 UI Action 使用恢复后的可见输入；`data.viewSource` 区分当前、历史和回传结果，`queryState.resultMatchesCurrentInput` 仅表示参数匹配，不表示历史结果已刷新。事件包原始输入未保存时保留草稿、明确不匹配，不从归一化结果伪造原始事件包。

页面与 Agent 的 `topAlerts[].detailLabels` 共用字段标签。Desk 代码查询的分红 `effective_at` 标为“除权除息日”，解禁标为“解禁日”；通用事件包仍为“生效日期”，不推定其业务含义。该展示补充不回写已保存快照。

Action：`analysis.event-flow`

HTTP：`POST /api/v1/event-flows`

输入支持两种互斥模式：

- 股票代码：`{"symbol":"300502","asOf":"2026-08-11"}`，`asOf` 可选。
- 事件包：`instock-event-flow-packet-v1`。

股票代码模式读取 Desk Research HTTP Interface 的主力资金、融资融券、龙虎榜、大宗交易、股东户数、分红送转和限售解禁，并通过 Desk Data Service capability 读取公告、研报与新闻。项目不直连旧 MySQL，也不恢复原抓取器。

每条事件包含：`id`、`type`、`symbol`、`occurred_at`、`title`、`direction`、`magnitude_score`、`evidence_strength`、`source_ref`，可带标量 `details`。支持公告、新闻、研报、主力资金、融资融券、龙虎榜、大宗交易、股东变化、分红、解禁、涨停原因、北向和机构资金类型。

## 处理规则

- 证券、事件类型、事件日期、方向及 `source_ref` 全部相同，才保留异常强度最高的一条。相同链接涉及不同证券、日期或相反方向时分别保留；这不是跨来源的语义去重，也不代表已判断哪种方向正确。
- 30 日内标记 `fresh`，超过 30 日保留审计但标记 `stale`。
- 异常强度 = magnitude 65% + 证据强度 25% + 时效 10%。代码查询模式的 magnitude 使用资金绝对值历史分位、公开成交额或公开比例形成研究优先级；事件包模式继续使用宿主提供值。
- 按证券汇总正向、负向事件数量与强度差。
- 输出 `coverage`、字段单位和 `failures`；空数据与接口失败分别披露。
- 公告、研报、新闻仅将明确的空列表记为空结果；列表中包含非对象记录时，该来源记为失败，不静默丢弃后伪报空或完整覆盖。Research 研报源须通过 HTTP 状态检查并明确返回对象列表；失败保留到事件快照及公司档案，其余可用来源继续展示。

公告、研报和新闻默认保持中性，不从标题自动推断涨跌。资金和筹码方向只描述已观察证据，不会把异常强度解释为收益预测或交易信号。

## 数值与股东披露日期（引擎 1.3.0）

- Research 股东户均映射 `AVG_HOLD_NUM`，口径为总 A 股股数/股东户数，不再误取不存在的 `AVG_FREE_SHARES` 后填零。`date`保留统计期，`published_at`取`HOLD_NOTICE_DATE`；当前接口仅返回最新窗口，不是完整历史股东库。
- 股东事件在已知披露日进入时间线，`details.observation_date`仍保留统计期。历史查询排除晚披露或披露日未知的数据；当前查询允许保留未知披露日，但明确数据缺口。供应商披露日期不等于已验证全部修订版本，仍不得声称完整点时数据。
- 大宗折溢价以成交价/当日收盘价计算，不能用前日收盘涨跌幅替代。全日加权值要求所有笔数的金额和折溢价有效，否则保持null、弱证据和待核验方向；不按缺失笔数为0折溢价稀释计算。有效笔数另列，真实0%保留。
- 缺数或缺披露日写入`data_quality_note`、部分数据状态和快照限制，下游公司档案继续展示缺口。股东数值和折溢价空项在UI显示`--`，口径/日期/缺口不再受前5项截断。
- 数据包明确提供`details.published_at`时校验不晚于截止日；引用旧快照时重新校验披露日期，历史股东记录缺日期则排除，不回写原快照。其他事件的资金短窗口、分红和解禁缺数处理仍需逐项核查。

## 资金窗口与分位（引擎 1.4.0）

- 主力和融资按日期倒序、同日去重，重复且数值一致只算一次，冲突字段保留未知。融资净额只由同日买入减偿还得到，不以余额差替代缺失偿还。
- `main_net_5d_cny` / `main_net_20d_cny` / `financing_net_5d_cny`保留已有字段身份，但含义为最近5/20个**有记录日期**的净额，并非已经核验连续交易日。窗口内缺数或返回不足条数均为null；不删掉缺失日期后向前补齐，不填零。
- `window_5d_*` / `window_20d_*`提供返回记录数、有效记录数、起止日期；页面和Context同时保留。不同日期范围、不同口径的资金指标不得直接相抵。
- 绝对净额分位仅在当前5条完整且此前至少20个完整5条窗口时计算。使用已有pandas `rolling(5, min_periods=5)`，缺数窗口排除但不压缩时间轴；不将当前窗口纳入参考，仍可能互相重叠，不视作独立样本或显著性检验。20窗口为展示门槛，不是统计有效性证明。
- 同值采用中位秩（低于比例+半个相等比例），避免全相等样本都显示100%。没有可用分位时字段null，研究优先级不赋予异常幅度分；有效方向和原始净额仍保留，部分证据限制继续传入公司档案。
- Research研究页也按日期取最近20条，不依赖东财/新浪的返回排序；融资与主力空值不显示0，原有数据时间不再由页面查询时钟冒充。来源错误保留HTTP状态与失败覆盖，不在事件资金失败明细中展示内部URL。

## 日期与下游引用边界

### 报道关联（引擎1.6.0）

- `related_groups` 只组织公告/新闻中同证券、同日、单一回购/增持/减持主题且同阶段的线索。终止、完成、进展、审议、提议计划分开；混合主题或市场综述不归组。标题匹配不能证明主体或方案相同，因此 `identity_verified=false`、`independent_source_count=null`。
- 原始`alerts`、来源链接、方向和评分全部保留；不因报道数增加证据强度，不做自动情绪判定，也不删除被关联的记录。证券强度汇总仍是记录级描述，不是独立事件数或多源确认。
- 页面优先展示组内公司公告，其余证据可展开。按方向筛选时保留被隐藏条数和全组相反方向提示，不能把筛选后的单边报道说成一致共识。Context的`relatedGroups`携带同样分组与筛选范围；历史引用按过滤后的证据重新计算，不回写原快照。
- 顶部“证据条目”不再写“有效事件”；来源响应同时列出有记录、空、失败数量，源窗口最新日期不冒充研究截止日内的覆盖。

### 分红与解禁（引擎1.5.0）

- Research分红使用东财`RPT_SHAREBONUS_DET.IT_RATIO`，不是不存在的`TRANSFER_RATIO`；派息、转增、送股均按每10股。数值缺失保持null，保留原始方案文字，不用缺项自动推断0。
- `NOTICE_DATE`作为供应商当前方案披露日，`PLAN_NOTICE_DATE`仅作预案披露参考，不能拿早期预案日期为后来的实施方案背书。除权日、登记日单独展示；无除权日的预案仍可展示，不能称现金已到账。按报告期读取最新窗口，避免只排序除权日漏掉未实施方案。
- 解禁`CURRENT_FREE_SHARES`是本批数量，`FREE_SHARES`是流通基数，不能互换。`ABLE_FREE_SHARES`保留可流通数量（万股）；`FREE_RATIO`为占流通股本的小数（0.0017359约0.17%），Research与事件页采用同一显示口径。
- 解禁历史查询限定日期早于查询日，当日归入当日/未来计划；日历不代表实际减持。源的`EUTIME`不能当披露日，目前该源`published_at=null`。
- 分红/解禁历史判断和旧快照引用排除晚披露/披露日未核验的记录，并保留排除提示；当日仍可展示未核验记录但标弱证据。已知披露日不晚于截止日的未来计划可保留，事件日期与生效日期分别存储。当前记录可能含修订，仍不是完整历史版本库。
- 两接口采用已有strict失败模式。东财实际空结果协议`success=false, code=9201, message=返回数据为空, result=null`单独识别为空；其他失败不能降级为空，空结果也不保证没有风险。
- 2026-10-20真实接口校验：300502分红原始方案`10转4股派10.00元`，披露2026-06-04、除权06-11，送股字段null；解禁153.4197万股、FREE_RATIO=0.001735906791。来源为东财公共数据中心；另对照已安装AkShare的`stock_fundamental/stock_restricted_em.py`字段映射。a-stock-data仅作接口参考，其中旧字段、每股文案和缺数填0示例未照搬。

- 代码查询读取当前数据窗口：当日标记 `latest_window`，历史截止日过滤标记 `partial_point_in_time`，不称完整历史点时数据。
- 事件包标记 `declared_event_dates`：`occurred_at` 是声明的事件日期，不保证在当时已公开。已提供的披露日期受截止日约束，但尚未建立全部事件的独立披露核验。
- 下游按截止日重放分别标记 `partial_point_in_time_replay` / `declared_event_dates_replay`。旧快照过强的标注仅在引用结果中纠正，原始标注保存在 `source_snapshot_resolution`，不回写原快照。
- 引用结果保留 `coverage`、`failures`、`limitations`、`warnings` 和 `data_state`；`coverage_scope=source_snapshot` 表示来源覆盖属于原快照，不冒充过滤后某只股票或日期的完整覆盖。
- 来源失败、空来源和缺覆盖记录传入公司档案/综合选股的缺口提示。缺失不是零风险；声明失败却没有失败明细的来源也不能标为完整。

## 跨页交接

公司事件进入公司档案时传递当前结果的证券、事件快照和截止日。Desk嵌入模式通过已有Bridge导航保持同一工作区；导航未就绪明确提示，不退到独立页面读取不同范围的快照。独立模式保留普通页面链接。编辑输入或重新握手后撤下旧交接入口；证券选择事件也携带证据截止日。

## 设计参考

本轮通过 search-first 研究公开源码，仅借鉴设计，不引入新框架：

- [OpenBB 公司新闻标准](https://github.com/OpenBB-finance/OpenBB/blob/develop/openbb_platform/core/openbb_core/provider/standard_models/company_news.py)：证券关联、来源链接及发布日期分开表达。不能仅凭链接去重就丢弃其他证券关联。
- [OpenBB SEC 披露](https://github.com/OpenBB-finance/OpenBB/blob/develop/openbb_platform/providers/sec/openbb_sec/models/company_filings.py)：报告日期与披露日期分开；本模块已接入股东披露日期，其他来源及历史修订核验仍待完成。
- [eventsourcing SQLite](https://github.com/pyeventsourcing/eventsourcing/blob/master/eventsourcing/sqlite.py)：身份及版本范围内去重，不把消费序号当业务时间。这并不提供金融事件语义去重。
- [NewsPrism](https://github.com/moguiyu/NewsPrism)：2026-10-20公开检索并阅读README，借鉴原始报道与关联组分层、多来源并列展示；其LLM/embedding聚类及影响评分未引入。当前先做显式可解释的待核验关联，不把关键词匹配包装成已验证的事件身份；没有安装该项目或新增模型依赖。

软件开源许可不等于新闻内容可自由再分发。
