# 研究组合合同

## 定位

`instock-research-book` 负责校验和汇总研究状态，不负责真实持仓或交易。前端按用户/工作区保存本机草稿，独立模式使用单独命名空间；这不是服务端多租户认证或跨设备同步。旧版全局草稿不删除、不自动认领。

## 接口

Action：`analysis.research-book`

HTTP：`POST /api/v1/research-books`

公司档案交接：`GET /api/v1/research-books?sourceSnapshotId=...&symbol=...&market=CN`。
网址仅传证券身份和来源快照 ID，接口核对来源后返回完整结论、张力、缺口和证伪条件。默认研究权重为 0，带入编辑器不等于加入或保存。旧快照缺少必要字段、来源已过期、证券/市场不一致时明确拒绝，要求回公司档案重新生成。

输入版本：`instock-research-book-packet-v1`。

每个观察项包含证券、行业、目标研究暴露、观察理由、至少一条证伪条件、风险标签和 0～10 个 Analysis Snapshot 引用。全部目标暴露之和不能超过 100%。

## 输出

- Snapshot 引用逐项核对证券、市场与来源截止日（不得晚于组合截止日）。不存在、日期缺失、未来数据、范围未知、市场/证券不一致分别说明。
- 引用匹配只表示来源范围符合，不代表研究主张已验证。来源覆盖不完整仍提示；人工复核属于单独的工作区记录，不写回公司快照。
- 行业、风险标签和最大单项暴露。
- 单项超过 20%、行业超过 40% 的集中度警告。
- 未分配研究权重、数据状态、限制和研究组合 Snapshot；旧字段 `cash_weight_pct` 保留兼容，但它不是真实现金。

目标权重只用于研究暴露汇总，不是资产配置建议。不下单，也不恢复原 InStock `attention` 表。

组合检查结果现保存到当前用户/工作区的分析历史与快照目录，可在历史面板回看，但不会替换左侧仍在编辑的草稿。Desk Action 转发签名会话，运行时向固定配置的 Desk 入口校验实例、模组版本与能力，再确定作用域。历史读取、公司交接、缓存与进行中的计算均沿用该作用域；校验失败不回退独立模式。

无会话的独立 API 属于 `standalone:local` 本地单用户范围，不与任何 Desk 工作区互通。升级前没有归属的 SQLite 记录保留为 `scope=NULL`，不展示、不自动认领、也不被新范围的容量/过期清理删除。

内存快照过期或服务重启后，按原快照 ID 从同范围的保留历史读取顶层快照，恢复产业链、公司档案到研究组合的引用。保留原生成时间、日期、证据和结论，不重新分析，不改变原始新鲜度字段；原新鲜度是分析当时状态，不代表当前行情。读取不追加历史或延长保留期，历史过期或被容量规则清理后仍不可恢复。没有保存过完整结果的内存快照、嵌套引用和无归属旧记录不会被自动恢复。

这不是公网多租户认证：当前 Desk 的会话签发仍接受本地调用方选择的用户与工作区。不得把会话签名当成已经验证了账户身份；公网部署还需要宿主身份认证。没有 Mod 会话的旧工作流/服务调用仍属于独立单用户范围，不能读取 Desk 私有快照。

编辑输入、切换用户/工作区和检查失败会撤下旧结果；迟到交接不覆盖用户编辑，迟到检查不跨工作区恢复。Agent 上下文包含当前观察项及其来源判断，界面和 Agent 不再一处显示风险、另一处只见汇总。

## 工作区人工复核（引擎 1.2.0）

- 已匹配的 CN 产业链引用复用公司档案的证券暴露解析器，只取所属节点的直接关系。多候选暴露歧义不选择第一条；错证券、晚于截止日或无法解析的引用不生成复核上下文。
- 检查结果仅携带公开关系与证据版本。前端通过 `POST /api/mods/instock-research-book/sources/chain-reviews`，使用当前签名会话读取指定关系的最新人工意见及相关归档版本。服务复用原公司档案端点，只授权这两个模组，核对用户、工作区、实例、权限和已发布版本。
- 复用公司档案的展示与匹配组件，区分直接支持、反证、证据不足、旧意见待复核、尚无意见和读取不可用。按来源顺序读取，可手动刷新；不是跨页面实时订阅。独立页没有 Desk 身份则明确不可读取，不猜身份。
- 人工意见单独进入页面与 Agent 的 `relationshipReviews`，不改变权重、不写入本机草稿、结果快照或研究组合检查输入。切换/编辑销毁旧读取器，撤下私有内容并忽略迟到响应。
- 意见为读取时的当前工作区判断，不是组合截止日当时已知的历史判断，更不是关系真实性或公司损失认证。缺少直接关系的观察项单独标记覆盖未知。

## 私有研究起点追溯（引擎 1.5.0）

- 公司档案成功读取已归档起点后，进入组合时只携带记录 ID、归属标识和产业链快照 ID；未读取成功、失败或工作区变化不声明已交接。网址不含原文或会话令牌。
- 观察项可带可选 `research_origin` 定位字段。服务只接受 `researchOriginId`、`originUserId`、`originWorkspaceId`、`snapshotId` 四个标识，拒绝原文等额外字段及未列入 `snapshot_ids` 的来源。草稿、同工作区结果历史保留该定位，不复制起点原文。
- 引用完成证券、市场、截止日与直接关系匹配后，组合复用原起点组件提供显式读取。接口 `/api/mods/instock-research-book/research-origins/{id}` 核对当前签名用户、工作区、实例、模块权限、发布版本及指定研究身份。前端声明的来源归属不代替会话授权。
- 原文、人工反证、待复核原因和日期限制只进入当次页面与 Agent 的 `researchOrigins`。不写进检查请求、结果快照、本机草稿或结果历史，也不改评分/权重。历史回看保留定位，但需重新读取原文，不覆盖正在编辑的草稿。
- 编辑证券或来源编号撤下编辑器中的旧起点关联；修改组合、切换工作区、读取失败或移除页面结果会清空原文并销毁旧读取，迟到响应不得回填。Agent 上下文同步核对作用域，不等待页面切换事件。
- 起点记录是归档研究线索，不是模型实际使用证明或企业关系认证。缺少/过期来源、暴露歧义、跨工作区引用均不显示可读取的已匹配起点；无起点的旧记录保持原功能。

## 研究理由与证伪条件对照（引擎 1.6.0）

- 输入合同不变。每个观察项新增输出 `thesis_review`，组合新增 `review_summary`。证券/市场/日期匹配与研究理由复核独立：`data_state=complete` 不等于投资逻辑成立。
- 仅比较本次显式关联且已匹配的公司档案，不扫描其他工作区或自动抓取最新快照。每个来源保留编号、截止日、原结论和原证伪条件；多版本分别展示，不合成为未经用户确认的新结论。
- 文字比较只归一化空白，不做语义推断。观察理由与来源文字不同、来源证伪条件没有按原文带入时提示人工复核，允许用户有独立观点或等价改写；不自动判定矛盾、条件命中或修改原草稿。
- 引用不匹配/不存在、来源覆盖不足、公司研究字段缺失和没有完整公司对照分别列明。来源时间差使用组合截止日减去来源截止日，不使用今天重解释历史；达到90自然日仅为季度复核提醒，不宣告资料失效。
- 状态 `text_aligned` 仅表示没有上述机械差异，`needs_review` 表示存在待核对事项。所有结果的 `condition_evaluation=not_evaluated`，从不按“条件已填写”推断“条件未触发”。
- 待复核研究暴露按观察项计一次，不随来源数或问题数累加；零权重观察项仍列入清单。类别可重叠，不可相加；百分比不是损失估计。页面按研究权重排序，点击定位对应观察项，不按结果索引修改另一份草稿。
- 历史结果保留当次对照，不追认旧引擎结果；旧记录显示须重新检查。编辑或工作区切换清空待办及Agent结论。当前工作区人工关系复核仍单独读取，不写入公开对照输出，不与历史截止日意见混同。
