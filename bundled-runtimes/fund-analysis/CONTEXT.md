# 简单基金选择工具

本项目帮助普通用户快速完成基金浏览、比较、研究、分析和候选选择。专业方法隐藏在后台，前台使用清楚的中文、图表、标签和可核验理由。

本项目首先是独立基金应用。Newma Desk 适配只位于单独的 Adapter seam，不得改变独立应用的页面、端口、数据库和业务规则。

## 产品入口

**找基金**：
搜索基金，查看基金详情、净值曲线、收益与风险指标，并选择多只基金进行比较。

**调研库**：
连接本地调研纪要文件夹，按基金经理和基金归档文件，从纪要中提取可引用的投资理念、能力圈、风险意识和风格标签。

**AI 分析**：
用户选择一只或多只基金后现场运行分析。分析使用基金数据库、调研纪要和业绩归因结果，并保存输入、证据、结果和时间，支持牛马 Desk Agent 对话调用。

**标签推荐**：
用户选择基金类别和主流风格标签，系统返回不超过十只候选基金，展示入选理由、主要风险、数据日期和可比较基金。

## 核心语言

**独立基金应用（Standalone Fund Application）**：
本项目的正式产品与唯一业务实现，前端固定使用 `127.0.0.1:3000`，后端固定使用 `127.0.0.1:8005`。它不依赖 Newma Desk，也不得复用 Orchestra 的 `3001` 端口。

**基金工作区壳（Fund Workspace Shell）**：
独立应用的 Rail、Project Panel、Toolbar、内容区和 Copilot 组成的工作区。它使用与 Desk Suite 一致的菜单身份和 Newma 视觉 Token；当正式页面嵌入 Desk 时，不再渲染这层壳。

**Desk 适配包（Desk Adapter Package）**：
`desk/`、`app/(desk)/`、`lib/newma-desk/` 和后端 Desk 能力路由组成的可选 Adapter。它只把正式基金页面、Context 和数据能力映射为一个完整 Suite，不复制基金业务实现，不直接向 Desk 控制面发布，验收前不得进入 `desk-mods`。

**基金实体（Fund Entity）**：
合并同一产品不同份额后的标准基金对象。份额费用仍单独保留，但不会把同一基金的多个份额重复推荐。

**基金分类（Fund Classification）**：
基金所属的资产类别、策略、主动或被动、地域、主题和风格。分类必须有来源和置信度；模糊时显示“待确认”。

**基金分类目录（Fund Classification Catalog）**：
策略族谱、同类组和可核验基准代码的正式定义。目录不包含演示基金，入库只能使用真实基金证据。

**风格标签（Style Tag）**：
由持仓、收益行为和调研纪要共同支持的标签，例如大盘成长、价值、均衡、小盘、质量、红利、行业主题和全球配置。标签必须展示证据来源，不能只靠名称猜测。

**同类比较（Peer Comparison）**：
基金只与同类别、同策略口径的基金比较。样本不足时不跨类别凑数。

**基金评价（Fund Evaluation）**：
用长期与滚动业绩、回撤、风险调整收益、上涨参与、下跌防守、稳定性、费用、规模、经理任期、风格一致性和数据质量说明基金的特点、优势和风险。

**基金研究快照（Fund Research Snapshot）**：
面向基金详情、候选推荐和 AI 分析的统一研究事实。一次输出基金实体、经理、分类、同类评价、风格标签、调研纪要、数据日期、证据缺口，以及按需运行的业绩归因，避免不同入口形成不同口径。

**调研画像投影（Research Profile Projection）**：
把人工确认后的纪要分类、风格标签及原文证据，投影为基金研究画像；标准同类组和基准必须来自基金分类目录，不允许由纪要猜测。

**基金经理浏览器（Fund Manager Browser）**：
按经理姓名、基金公司和标准基金类别查找基金经理，展示当前管理基金、代表基金、专业分类、基金评价、任期指标和调研纪要覆盖。它帮助用户进入经理研究，不按跨类别短期收益给经理排总榜，也不承载购买、销售规则或投资处置。

**基金经理纪要画像（Fund Manager Memo Profile）**：
把已确认归属于同一基金经理的调研纪要聚合为产品定位、投资目标、投资方法、投资理念、选股逻辑、风险意识、能力圈、能力优势与边界、组合集中度和换手特征。每个画像字段必须保留来源纪要、原文摘录、日期和置信度；没有原文证据的字段保持为空，不生成默认分数。

**基金经理产品任职（Manager Product Tenure）**：
保存经理现任和历史管理产品的真实起止日期，并按基金实体合并 A/C 等份额。经理详情中的产品数按实体统计，份额代码仍可追溯；任期收益、年化收益、回撤、波动和 Sharpe 必须由该经理在该产品任期内的真实净值计算，不用近一年指标代替。

**同类任期排名（Manager Tenure Peer Rank）**：
把经理在具体产品上的任期收益，与相同专业同类组中同一日期区间、净值覆盖充足的基金实体比较。排名必须展示名次、有效样本数、同类组和区间；目标基金使用该经理真实任期收益，其他基金使用同区间真实净值。样本不足时不生成排名。

**选基首页（Fund Selection Home）**：
面向普通用户的统一起点，只聚合基金数据库、可用同类候选、基金经理、调研纪要和自选基金的真实摘要，并把用户引导到对应核心模块。首页不生成择时信号、资产配置建议、购买结论或跨类别排名。

**业绩归因（Performance Attribution）**：
解释收益和风险来自哪里。Brinson 用于配置与选择效应，因子模型用于风格和风险暴露。归因季度默认使用上一季度已披露持仓，避免用期末持仓倒推已经发生的收益；公开持仓覆盖不足时必须展示覆盖率和残差。净值行为解释只能作为补充证据，不得标记为 Barra 或 Brinson。数据不足时不得输出专业模型结论。

**AI 分析记录（AI Analysis Record）**：
一次由用户主动发起的分析，包含分析对象、使用的数据和纪要、归因结果、提示词版本、模型、生成时间、引用和最终结论，可在历史记录中重新查看。

**候选推荐组（Recommendation Set）**：
按用户选择的类别和风格标签，从同类基金中筛出最多十只候选。每只基金必须给出入选理由、风险、证据日期和数据完整度。候选推荐不等于个性化投资建议，也不执行交易。

## 禁止事项

- 不用单期收益冠军直接推荐基金。
- 不把不同类别基金放进同一评分池。
- 不让 LLM 编造净值、持仓、经理经历、风格或归因结果。
- 不将调研纪要中的观点当作事实，必须区分原文、提取标签和系统判断。
- 不开发购买金额、销售规则、适当性、交易执行、观察池晋级或尽调工作流。
