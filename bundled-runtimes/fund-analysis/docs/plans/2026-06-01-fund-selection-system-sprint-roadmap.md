# 基金选择评价系统 Sprint 路线图

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this roadmap task-by-task.

**Goal:** 将当前项目从“具备基金数据、评分、分析页面的研究系统”推进为“具备候选池管理、预警跟踪、基金对比和研究结论沉淀能力的基金选择评价系统”。

**Architecture:** 基于已落地的数据血缘、指标快照、评分契约和市场浏览器能力，下一阶段优先补齐投研闭环，再加强选择能力，最后承接组合与回测。FastAPI 继续作为研究计算主后端，Next.js 继续作为工作台与 BFF。

**Tech Stack:** Next.js App Router, TypeScript, FastAPI, Python, PostgreSQL, Prisma, Qdrant, Redis(optional), existing scoring/metrics/report infrastructure.

---

## Sprint A：闭环能力（最优先）

### 核心目标

把“基金浏览 → 候选研究 → 持续跟踪”这条主链路打通。

### 交付主题

1. 基金池工作流
2. 预警中心
3. 页面级可信度展示

### 用户价值

- 用户可以把筛选/浏览结果转化为候选池资产
- 用户可以知道哪些基金值得复查
- 用户可以看到系统结论到底基于什么数据

### A1. 基金池工作流

**目标**
- 建立候选池、观察池、核心池、淘汰池的状态流转

**后端任务**
- 新增 `FundPool` 与 `PoolMember` 数据模型
- 新增 Pool repository 与状态迁移方法
- 提供 API：
  - 创建基金池
  - 获取基金池列表
  - 添加基金到池
  - 更新基金状态
  - 查询某状态下的基金

**前端任务**
- 新增基金池页面
- 从全市场基金浏览器增加“加入候选池”入口
- 从筛选器结果增加“加入候选池”入口
- 展示字段：
  - 基金名称
  - 当前评分
  - 入池时间
  - 入池理由
  - 最近结论
  - 下次复查时间

**验收标准**
- 用户能从 `/market` 把基金加入候选池
- 用户能在基金池页面看到状态化基金列表
- 用户能手动将基金从候选池流转到观察池/核心池/淘汰池

### A2. 预警中心

**目标**
- 建立系统“买后跟踪”能力

**后端任务**
- 新增 `AlertRule` 与 `AlertEvent`
- 实现基础预警扫描服务
- 第一批规则：
  - 回撤超阈值
  - 评分下滑
  - 风格漂移
  - 经理变更
  - 规模异常变化

**前端任务**
- 新增预警中心页面
- 支持按状态筛选：未处理 / 已确认 / 已忽略
- 支持查看触发规则和关联基金
- 支持跳转到基金详情和基金池条目

**验收标准**
- 系统能产生基础预警事件
- 用户能看到预警列表并处理状态
- 核心池和观察池基金能被持续监控

### A3. 页面级可信度展示

**目标**
- 让用户直接看到分析结论的可信基础

**后端任务**
- 扩展基金详情/评分接口，返回：
  - 数据截止日期
  - 最近同步时间
  - 评分时间
  - 缺失数据项
  - 数据完整度
  - 使用的 source snapshot ids

**前端任务**
- 在基金详情页增加“数据可信度面板”
- 在评分结果区增加“缺失数据/加分项/扣分项”展示
- 在 AI 报告区预留“证据数”与“引用块数”位置

**验收标准**
- 任意基金详情页都能显示数据截至日期
- 任意评分结果都能展示缺失数据和得分解释

## Sprint B：选择能力强化

### 核心目标

把“看基金”升级为“选基金”。

### 交付主题

1. 基金对比工作台
2. 同类分位与基准对比
3. 研究结论对象化沉淀

### 用户价值

- 用户可以在多个候选基金之间做优选
- 用户可以知道一个基金是“绝对优秀”还是“相对优秀”
- 用户可以复用历史研究，而不是重复研究

### B1. 基金对比工作台

**目标**
- 支持 2-5 只基金横向对比

**后端任务**
- 新增基金对比 API
- 聚合基金基础信息、评分、指标快照、风格暴露、归因结果
- 输出结构化差异结果

**前端任务**
- 新增基金对比页面
- 支持从市场浏览器和基金池勾选基金加入对比
- 展示维度：
  - 收益与风险
  - 同类分位
  - 回撤修复能力
  - 持仓集中度
  - 因子暴露
  - AI 结论对比

**验收标准**
- 用户能在界面上对比至少两只基金
- 系统能给出“更优候选”的结构化提示

### B2. 同类分位与基准对比

**目标**
- 建立真正的相对评价体系

**后端任务**
- 新增 `Benchmark` 和 `PeerGroup` 实体或规则集
- 计算同类分位、同类平均差值、基准超额收益
- 将相对指标写入 `MetricSnapshot`
- 将同类分位接入评分解释

**前端任务**
- 在基金详情页展示：
  - 同类分位
  - 基准超额
  - 与同类前 25% 偏差
- 在基金对比页展示相对排名

**验收标准**
- 至少一个基金类别支持稳定的同类分位显示
- 评分系统可以识别“绝对收益一般但相对同类优秀”的情况

### B3. 研究结论对象化（Research Insight）

**目标**
- 把研究结论从文本升级为结构化对象

**后端任务**
- 新增 `ResearchInsight` 数据模型
- 支持保存：
  - 结论
  - 核心逻辑
  - 证据列表
  - 风险点
  - 置信度
  - 有效期
- 支持基金级和经理级结论时间线

**前端任务**
- 在基金详情页增加“研究结论时间线”
- 在基金池中展示最近有效结论
- 在对比页展示多基金结论摘要

**验收标准**
- 用户能查看某基金历史结论变化
- 入池理由与研究结论可以关联

## Sprint C：研究资产与证据链

### 核心目标

让 AI 与报告系统真正成为投研证据系统，而不是摘要生成器。

### 交付主题

1. ResearchReportChunk 落地使用
2. 报告证据块搜索
3. AI 报告强制引用证据

### C1. Report Chunk Pipeline

**任务**
- 完成 `ResearchReportChunk` 真正入库流程
- 文档切片、token_count、embedding_id、entities 写入 PostgreSQL
- Qdrant payload 与 chunk 元数据一一对应

### C2. Chunk 级搜索 API

**任务**
- 返回 report id、chunk id、chunk index、score、content snippet、metadata
- Next.js 搜索入口逐步改为代理 FastAPI

### C3. AI 报告证据化

**任务**
- AI 报告输出中强制包含 evidence blocks
- 前端显示“引用证据”与“反方观点”

**验收标准**
- 任意 AI 报告可追溯到 chunk 级证据

---

## Sprint D：组合承接与复盘

### 核心目标

把基金选择系统进一步升级为组合支撑系统。

### 交付主题

1. 组合诊断
2. 替代基金建议
3. 策略回测骨架

### D1. 组合诊断

**任务**
- `Portfolio`、`PortfolioHolding`
- 组合收益、相关性、集中度、风格暴露
- 组合风险解释

### D2. 替代基金建议

**任务**
- 从候选池或全市场池中为组合基金提供替代项
- 基于风格接近度 + 评分优势 + 回撤特征输出替代建议

### D3. 策略回测骨架

**任务**
- 从筛选模板生成历史回测任务
- 保存回测摘要结果，先不做复杂交易仿真

## 迭代顺序建议

### 最推荐顺序

1. Sprint A
2. Sprint B
3. Sprint C
4. Sprint D

### 原因

- Sprint A 解决“能不能形成投研闭环”
- Sprint B 解决“能不能真正帮助选基金”
- Sprint C 解决“AI 和研究是否可信”
- Sprint D 解决“能不能承接组合层需求”

---

## 依赖关系

- Sprint B 依赖 Sprint A 的基金池工作流，因对比结果应能转化为池内动作
- Sprint C 依赖当前已建立的向量库主路径、报告切片模型和后续 chunk pipeline
- Sprint D 依赖前置评分、对比、基金池和预警体系

---

## 研发组织建议

### 后端优先

建议每个 Sprint 先完成：

1. 数据模型
2. Repository
3. Route
4. Service
5. Smoke tests

然后再做：

6. Next.js 页面
7. 页面联动入口
8. 文案和交互优化

### 验证优先级

- 仓储和服务层先做 deterministic smoke tests
- 路由层做 import/contract smoke tests
- 有数据库时再做完整集成验证

---

## 成功标准

如果完成 Sprint A + Sprint B，系统就基本具备“基金选择评价系统”的核心形态，能够回答：

1. 全市场里我先看谁？
2. 这些候选里我选谁？
3. 为什么选它，不选另一个？
4. 选完之后我该跟踪什么？
5. 哪些基金现在值得复查？

这五个问题能被系统稳定回答，说明产品已经从“研究分析工具”进入“投研决策系统”阶段。
