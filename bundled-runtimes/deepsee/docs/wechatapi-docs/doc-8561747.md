> 本文档从「管理后台 Token + 设备扫码登录」类控制台行为抽象而来，不绑定任何变量名、框架或文件结构。实现者可自行命名与分层。

## 1. 业务目标与前置条件

### 1.1 目标

在已持有**管理后台颁发的 API 令牌**的前提下，为某一「设备会话」完成：申请登录二维码 → 用户扫码 → 服务端推进登录态 → 客户端确认会话已建立并可获得用户标识信息。

### 1.2 前置条件

- 用户已配置有效令牌；所有业务请求须在请求头携带该令牌。
- 已存在或可分配**设备标识**（首次可为空，由服务端分配后回填）。
- 用户选择**地区**与**终端形态**（影响后续「轮询」请求中的一个布尔参数）。

---

## 2. 核心概念（中立术语）

| 概念 | 含义 |
|------|------|
| API 令牌 | 管理后台颁发，用于调用网关；与微信用户口令不是同一事物。 |
| 设备标识 | 绑定当前模拟/托管设备的字符串；首次取码可由服务端返回，重连可携带历史值。 |
| 会话票据 | 一次取码流程中服务端返回的、与当前二维码绑定的短生命周期标识（下文称「取码票据」）。 |
| 终端形态 | 至少两类：一类对应「可自动滑块」策略，另一类对应「不可自动滑块」策略。 |
| 取码票据 TTL（客户端） | 客户端在取码成功后启动的**本地**截止时间；超时则停止轮询并要求重新取码（与服务端过期字段可独立存在）。 |
| 轮询 | 固定时间间隔重复调用「检查登录状态」接口，直到进入终止态。 |
| 二次验证 | 某终端形态下，检查接口可能返回「验证资源地址」；用户完成外部验证后，再继续轮询。 |

## 3. 状态与终止条件（状态机语义）

### 3.1 建议的客户端阶段

1. **空闲**：未取码或未轮询。
2. **已取码、待轮询条件满足**：若设备标识或取码票据尚未就绪，不得递增轮询计数；仅展示等待文案。
3. **轮询中**：周期性调用检查接口。
4. **等待二次验证**：已停止定时轮询；展示验证用资源；用户确认后继续轮询（可重置本地取码 TTL 计时起点，由产品决定，规范建议与「重新取码」策略一致并文档化）。
5. **成功**：检查接口返回的「用户信息载体」被判定为**非空且含实质字段**即视为成功（**不得**唯一依赖某一整型状态码等于「成功」枚举值）。
6. **用户主动取消（服务端语义）**：检查接口返回明确「已取消」语义时，停止轮询并清空或要求重新取码。
7. **本地取码超时**：超过客户端 TTL 停止轮询。
8. **致命传输错误**：单次检查请求发生网络级失败或不可解析响应时，**停止轮询**（与「业务码非成功仍继续轮询」区分）。

### 3.2 成功判定（必须写进规范）

当检查接口的业务信封为成功，且载荷中「用户信息载体」满足：**为对象、非数组、非空键集合，且至少一个字段为非空字符串、数值、布尔值或非空对象** —— 则判定登录成功。头像 URL 可在载荷顶层存在时需合并进用户信息载体以便展示。

### 3.3 与「状态码字段」的关系

若载荷中存在「进度类整型字段」（如未扫码、已扫码、成功、取消等），**仅用于 UI 展示与排障**；**成功判定仍以用户信息载体为准**。

## 4. 接口契约（API Definitions）

> 以下路径为相对网关基址的 path；方法均为 **POST**；正文为 **JSON**。除特别说明外，设备标识若未在 JSON 中显式出现，网关实现**可**统一合并当前会话设备标识（实现者须二选一并在全站一致：**显式每请求携带** 或 **网关层自动合并**，本文推荐**检查类请求显式携带设备标识与取码票据**以避免歧义）。

### 4.1 公共约定

- **请求头**：`Content-Type: application/json`；`VideosApi-token`（或等价名）= API 令牌字符串。
- **业务信封**（示意）：`{ ret: number, msg?: string, data?: object }` — `ret` 表示业务层是否成功（实现者以文档为准，常见为 200 表示成功）。
- **令牌失效**：若 `msg` 命中约定子串（如不可用、已过期），客户端应将令牌状态标为无效并提示重新申请。

### 4.2 取登录二维码

- **Path**：`/login/getLoginQrCode`
- **Body 字段**：
  - `appId`（string，可选）：已有设备填之；首次可为空串。
  - `proxyIp`（string，可选）：代理描述。
  - `regionId`（string，**必填**）：地区编码。
  - `type`（string，**必填**）：终端形态枚举，如 `mac` / `ipad`。
- **成功载荷中客户端关心的字段**：
  - 二维码展示数据：以下**至少其一**非空 — `qrUrl`（URL）、`qrImgBase64`（Base64）、`qrCode`（可与 Base64 同义）。
  - `appId`：若存在则作为**当前流程设备标识**（可与请求中一致或为新分配）。
  - `uuid`：取码票据，后续检查请求**必须**携带。
- **失败**：不启动轮询；展示错误信息。

### 4.3 检查登录状态（轮询）

- **Path**：`/login/checkLogin`
- **Body 字段**（建议全部显式，避免依赖隐式合并）：
  - `appId`（string，**必填**）：取「当前内存会话设备标识」与「取码刚返回的临时设备标识」的**解析规则**：若会话已有设备标识则用之，否则用取码返回的临时设备标识。
  - `uuid`（string，**必填**）：取码返回的取码票据。
  - `autoSliding`（boolean，**必填**）：当终端形态为「可自动滑块」一类时为真，否则为假。
  - 可选扩展：`captchCode`、`proxyIp` 等以接口文档为准。
- **成功信封下载荷分支处理**：
  - **用户取消**：某一约定整型值（如 4）表示取消 → 停止轮询，提示重新取码。
  - **二次验证**：当终端形态为「需外部验证」类且载荷出现**非空验证资源**（如 URL）→ 停止轮询，进入二次验证 UI；用户确认后继续轮询。
  - **登录成功**：按第 3.2 节判定用户信息载体 → 停止轮询，进入已登录 UI，持久化会话所需字段。
  - **否则**：继续轮询；若信封非成功或载荷异常，**可不停止轮询**（与网络致命错误区分），但应节流日志避免刷屏。
- **客户端取码 TTL**：每次**重新开始**取码成功后的轮询计时起点；超过阈值必须停止轮询并提示重新取码。

### 4.4 辅助接口（非扫码主链路，但常同页出现）

- **检查在线**：`/login/checkOnline` — Body 通常仅需设备标识（可依赖合并规则）；成功时 `data` 为布尔表示是否在线。
- **断线重连**：`/login/reconnection` — 需已有设备标识。
- **退出登录**：`/login/logout` — 需设备标识及文档要求的其它字段；**建议**带有限次数重试与固定退避，失败仍执行本地清理策略（由产品决定）。

### 4.5 会话恢复（可选）

- 若仅存在设备标识而无完整用户信息，可调用个人资料类接口（如 `/personal/getProfile`）补全展示；失败时静默保留本地快照（若有）。

## 5. 持久化与隐私（中立要求）

- **主会话存储**：API 令牌、令牌校验状态、设备标识、取码票据（仅取码流程有效期间）、展示用昵称等；存储介质可为浏览器本地存储或移动端安全存储。
- **展示快照**：可单独存储头像、昵称、wxid 等**非令牌**字段用于冷启动展示；**不得**将 API 令牌写入仅用于 UI 快照的存储桶。
- **清理**：用户退出或「清理环境」时，应清除令牌、设备标识、取码票据、快照与运行期日志环形缓冲。

## 6. 并发与时间（中立）

- 轮询间隔：固定间隔（如 5s）+ 取码后立即执行首次检查。
- 同一时刻仅允许**一个**轮询调度器（避免重复 `setInterval`）。
- 取码请求进行中应禁止重复提交取码（按钮级互斥即可）。

## B. 业务流转逻辑（Workflow）

你必须用**步骤列表或流程图描述**并在代码注释中重复关键顺序：

1. **初始化**：从持久化恢复 API 令牌、设备标识；不自动开始轮询。
2. **校验输入**：地区必选；令牌非空；终端形态已选。
3. **取码**：调用取码接口；成功则解析二维码数据源并渲染；保存**取码票据**与**流程内设备标识**；启动**单一**轮询调度器并立即执行第一次检查。
4. **轮询循环**（每 Δt）：
   - 先判断客户端取码 TTL；超时 → 停止调度，提示重新取码。
   - 再判断设备标识与取码票据是否齐全；不齐 → 不增加轮询计数，UI 提示等待。
   - 调用检查接口：
     - **网络/解析失败** → 停止调度，记录错误，提示用户（是否允许「一键恢复轮询」由 README 说明）。
     - **信封或载荷异常** → 记录告警文案，**默认继续**调度（与规范一致）。
     - **取消语义** → 停止调度。
     - **二次验证资源出现**（限定终端形态）→ 停止调度，打开验证 UI。
     - **用户信息载体满足成功判定** → 停止调度，合并头像字段，进入已登录态，持久化。
5. **二次验证后继续**：关闭验证 UI，提示用户在手机端确认；**重启**调度器并明确是否重置 TTL 起点（须与 README 一致）。
6. **停止轮询**：用户按钮或上述终止条件触发；释放调度器。
7. **退出/清理**：调用退出接口（带重试与退避），清除本地敏感与半敏感数据，刷新或回到未登录态。

## D. 生产级工程质量要求

### D.1 防封控 / 友好限流（Anti-abuse）

- 轮询间隔 **不得** 低于产品约定下限（默认 5s）；禁止在错误分支中无退避地「紧循环重试」。
- 对同一错误类（如连续 `ret` 失败）可实现**指数退避**或**最大连续失败次数后暂停**（若实现退避，须在 README 声明与规范「继续轮询」的差异）。
- 日志中**默认脱敏** API 令牌；导出日志时替换为占位符。
- 所有用户可见错误文案**不得**泄露内部栈信息；开发模式可开关详细堆栈。

### D.2 异步解耦（Async decoupling）

- **UI 线程**：取码、单次检查、重试退出等 `await` 不得阻塞渲染；长任务拆分为可取消任务（组件卸载或路由离开时取消进行中的检查**可选**，但至少停止调度器）。
- **状态更新**：轮询结果 → 单一状态归约函数（reducer）或状态机类，避免多处分散赋值导致竞态。
- **与二次验证的衔接**：验证完成 → 仅允许通过**唯一入口**重启轮询，避免重复订阅。

### D.3 全链路日志（Full-chain logging）

每条记录至少包含：**时间、路径、合并后的请求体摘要（脱敏）、HTTP 状态、业务 ret、耗时、异常信息**。  
成功与失败均需记录；**批量静默轮询**时仍应采样或聚合日志（例如每 N 次写一条摘要）以防磁盘爆量——若采用采样，须在 README 明示。

### D.4 其它工程要求

- **单测/契约测**：对「用户信息载体成功判定」「取码票据解析」「二维码数据源三选一优先级」提供表驱动测试用例。
- **可配置常量**：网关基址、Δt、客户端取码 TTL、退出重试次数与退避、令牌失效子串列表。
- **无障碍与国际化**：错误与成功提示可切换语言键（可选）。

|------|------|
| 设备标识 | 与登录会话绑定的实例 id；所有请求正文若未显式带设备标识，由网关客户端层合并。 |
| 原始三类列表 | 接口返回的三组字符串 id：`friends`、`chatrooms`、`ghs`（命名以网关文档为准）。 |
| 归一后三类列表 | 经过去重、误分类纠正后的三组 id，用于 UI 与缓存。 |
| 详情映射 | 从「用户标识 → 详情行对象」的映射；一行至少含 `userName`（可与 id 大小写不一致）。 |
| 锁定目标 | 用户从列表中指定的**单一**操作对象 id；写入全局会话并持久化，供其它模块预填。 |
| 详情补全流水线 | 在拿到归一列表后，按批调用「批量详情」接口合并展示名（备注优先）。 |

---

## 3. 标识归一与三分类规则

**字符串归一**：去除首尾空白；将全角 `@` 规范为半角 `@`（若环境存在该字符）。

**群聊判定**：归一后 id 的小写形式以 `@chatroom` 结尾。

**公众号判定**：归一后 id 的小写形式以 `gh` 开头。

**归一算法（必须实现）**：

1. 对原始 `friends`、`chatrooms`、`ghs` 分别**去重**（保持顺序或稳定无序均可，但须文档化）。
2. 遍历原始 `friends` 中的每一个 id：
   - 若符合群聊判定 → 归入「误放在好友中的群」集合。
   - 若符合公众号判定 → 归入「误放在好友中的号」集合。
   - 否则 → 归入**好友列表**。
3. **群聊列表** = 原始 `chatrooms` ∪ 误归类群，再全局去重。
4. **公众号列表** = 原始 `ghs` ∪ 误归类号，再全局去重。

**Tab 展示二次过滤**：在某一 Tab 内渲染时，对传入的完整列表再滤一层，保证好友 Tab 不出现群/号 id，群 Tab 仅 `@chatroom`，号 Tab 仅 `gh` 前缀（与上规则一致）。

---

## 4. 展示名解析规则

对详情行对象（若不存在则仅 id）：

1. `remark` 非空字符串 → 用作展示名。  
2. 否则 `nickName` 非空 → 用作展示名。  
3. 否则 `userName` 非空 → 用作展示名。  
4. 否则 → 展示名为 id 本身。

**详情映射键**：须同时支持 `userName` 原始值与小写键，以便与列表 id 大小写不一致时仍能命中。

---

## 5. 详情补全流水线（核心）

**输入**：归一后的三组 id 合并为「全量 id 列表」（去重）。

**空列表**：清除通讯录缓存；三 Tab 显示空态文案；终止。

**非空**：

1. 初始化空的「详情映射」与「最近一次渲染上下文」（三组 id + 映射）。
2. **立即**用空映射渲染三 Tab（每行主标题为 id，副标题为 id），避免长时间白屏。
3. 将当前归一结果与当前映射（可能仍空）**写入本地通讯录缓存**（见第 8 节）。
4. 将全量 id 列表按固定批量大小 **N**（典型 20，不得超过接口上限）切片为若干批。
5. **并发度** **K**（典型 3）：维护至多 K 个工作者，从批队列取批顺序执行；每批调用「批量详情」接口，请求体为 `{ wxids: 该批 id 数组 }`。
6. 若存在**锁定目标 id**，对批队列排序：**包含该 id 的批次优先**（大小写归一比较）。
7. 每一批：
   - 使用「单批最长等待时间」**T**（典型 90000 ms）与请求组合 **竞态超时**；超时或任意失败 → 记录**全链路日志**（含本批 wxids、合并后请求体、错误），**跳过该批**，其它批继续。
   - 若业务信封成功且 `data` 为数组 → 将数组行合并进详情映射（按第 4 节键规则）。
8. 每批进入 `finally` 语义时：递增「已完成批次数」；触发**合并 UI 刷新**（见第 6 节）；更新进度状态条文案。
9. 全部批结束后：取消未执行的合并刷新任务（若存在）；**再完整渲染三 Tab**；根据详情映射**同步锁定目标的展示名**（若锁定 id 在列表中且详情行存在）；**再次写入**本地通讯录缓存（此时含详情行）。

**与接口日志策略**：批量补全单批请求默认**不**写入「模块主 API 日志流」（避免刷屏），但失败/超时必须在主日志或等价通道记一条带「本批已跳过」语义的记录。

---

## 6. UI 刷新合并策略

在批量补全过程中，多次映射更新应通过**下一帧合并**（例如显示列表刷新调度：若已有待执行帧任务则取消后重新注册），避免每批结束都全量重绘导致卡顿。

---

## 7. 锁定目标与会话

**设置目标**：用户在三 Tab 任一行触发「设为目标」时：

- 将锁定 id 写入全局会话；将展示名写入全局会话（按第 4 节从详情行解析）。
- 持久化全局会话。
- 若存在「最近一次渲染上下文」，**立即**按当前映射重绘三列表；并将与锁定 id 匹配的行排序置顶且视觉高亮（产品可调整）。

**预填**：所有标记为「可预填 wxid」的输入框在获得焦点时：若当前值为空且全局会话存在锁定 id，则填入锁定 id。

**横幅与提示**：顶部或模块内展示「当前锁定目标」的人类可读行（展示名 + id）；各输入框下方小字随输入变化刷新。

---

## 8. 本地通讯录缓存（版本化）

**存储内容**（概念 schema，须 `version` 字段）：

- `version`：固定为 `1`（未来升级递增）。
- `savedAt`：毫秒时间戳。
- `appId`：写入缓存时的会话设备标识。
- `friendsIds` / `chatroomIds` / `ghIds`：三组字符串数组。
- `details`：从详情映射导出的**去重**行对象数组（按 `userName` 小写去重，避免映射中双键重复）。

**恢复规则**：

- 读取失败或 `version` 不匹配 → 视为无缓存。
- 若「当前会话设备标识」与「缓存中设备标识」**均非空且不相等** → **拒绝恢复**（防止串设备）。
- 否则恢复三组 id 与详情行，重建渲染上下文并渲染；显示短时提示「已从本地缓存恢复…」。

**清除**：空通讯录时清除缓存；用户执行「清理环境」时与其它键一并清除。

## 3. 接收人解析规则（必须实现）

**从输入得到真实接收人标识**：

1. 取输入字符串首尾去空白。  
2. 若为空串 → 无接收人。  
3. 否则按**第一次**出现的分隔截取**左侧**子串作为候选标识：分隔符为全角左括号 `（` 或半角左括号 `(`。  
4. 对左侧子串再次首尾去空白 → 作为**真实接收人标识**。

**说明**：允许用户粘贴或展示为 `wxid_xxx（备注名）`，接口不得收到括号及以后内容。

## 4. 与全局会话及本地持久化的同步

**读取顺序（用于解析展示名或同步输入框）**：

1. 自输入框按第 3 节解析出的标识（若存在）。  
2. 否则使用全局会话中的锁定目标标识。  
3. 否则从「主会话持久化存储」读取锁定目标标识与展示名（与通讯录等模块共用同一存储桶时须 schema 一致）。

**同步到输入框（进入消息视图或用户显式触发「同步」时）**：

1. 若全局会话缺少锁定标识但持久化中存在 → 写回全局会话并持久化（避免刷新后丢失）。  
2. 计算展示名：优先全局会话展示名（且不得把展示名误当作与标识相同的字符串）；其次持久化中的展示名；再次可选「通讯录缓存反查展示名」函数（若平台提供）；否则空。  
3. 若锁定标识非空：输入框赋值规则——若有非空展示名且展示名与标识在归一比较下不相同 → 赋值为「标识 + 全角括号 + 展示名 + 全角右括号」形式；否则仅赋标识。  
4. 可选：清除或隐藏「目标已解析」辅助展示区（若产品需要可改为显示解析后的标识）。

**同步按钮反馈**：可在操作后 Toast：若同时有标识与展示名则组合提示；仅有标识则提示 wxid。

## 2. 术语

| 术语 | 含义 |
|------|------|

## 4. 信息流拉取与翻页

### 4.1 大厅时间线

- **路径**：`/sns/snsList`  
- **正文（概念）**：
  - 首次加载：`maxId = 0`，`firstPageMd5 = ''`（空串），`decrypt = true`（与当前实现一致，表示需要可展示解密数据，具体语义以网关为准）。
  - 翻页追加：使用**当前大厅游标**中的 `maxId` 与 `firstPageMd5` 填入同上键名。
- **成功后**：用响应 `data` 更新大厅游标（若字段存在则覆盖）；将列表**追加或替换**到 UI（首次应清空再渲染，翻页在列表尾部追加）；刷新游标展示文案。

### 4.2 指定好友时间线

- **路径**：`/sns/contactsSnsList`  
- **正文**：`wxid` 必填；`maxId`、`firstPageMd5`、`decrypt` 规则同大厅；**首次**与**翻页**区分与大厅相同。  
- **成功后**：更新「好友游标」三字段；列表处理同大厅。  
- **下一页时好友标识回退**：若输入框为空，则使用好友游标中已记录的 `wxid`。

### 4.3 列表提取与空态

- 从 `data` 取列表：**优先**文档主字段，**否则**备用字段；若非数组则视为空列表。  
- 若无任何卡片子节点则显示「空列表」提示。

### 4.4 业务失败与传输失败

- **列表类**：若 `ret !== 200`，应提示用户（使用 `msg` 或默认短文案），**不**更新游标与列表（或仅部分更新策略须在 README 固定；当前参考为不应用页）。  
- **传输/解析失败**：写日志 + Toast；返回空响应句柄。

## 5. 动态数字标识（snsId）传参规则

输入来自表单或卡片上的字符串：

1. 去空白。  
2. 须为**纯数字串**正则通过；否则视为非法，禁止发请求并提示。  
3. 若数字串长度超过约定阈值（典型 **15**），则以**字符串**原样放入 JSON，避免浮点精度丢失。  
4. 否则转换为数值：若仍在语言安全整数范围内则用数值类型；否则仍用**字符串**。

## 6. 动态卡片渲染（客户端解析）

对列表中**每一条**动态：

- **容错**：单条解析异常不得阻断其它条目；应记录占位错误卡片或日志并跳过。  
- **展示字段**：发布者昵称、用户名（微信号/wxid）、创建时间、从 XML 解析的文案、从 XML 提取的若干 `http` 缩略图 URL（上限可配置，典型 6）、点赞数/评论数、动态数字标识字符串。  
- **文案解析**：自 `snsXml` 中解析 `contentDesc`：优先结构化解析；失败则正则匹配 CDATA/纯文本节点；再对 HTML 实体与换行转义做可读化还原。  
- **缩略图解析**：正则匹配 `thumb` 标签内 CDATA 或文本，收集以 `http` 开头的 URL。  
- **时间展示**：支持秒级或毫秒级 Unix 时间戳的启发式（小于某阈值则按秒乘 1000）。  
- **外链图片**：使用不携带引用站点信息的图片策略（如 `no-referrer`），懒加载可选。

### 6.1 卡片内快捷操作

- **点赞**：调用点赞接口，`operType` 为「点赞」枚举值；正文须含动态标识、**发布者用户名**（缺失则禁止请求）、`useProxy: true`（与当前实现一致）。  
- **私聊跳转**：将发布者用户名与昵称写入全局锁定目标并持久化；导航到消息模块路由（产品可改为打开弹窗而非改路由）。

2. **刷新大厅**：调用大厅列表接口（非追加模式）→ 重置大厅游标起点 → 清空 feed → 应用响应 → 渲染卡片。  
3. **大厅下一页**：追加模式 → 使用当前大厅游标调用 → 尾部追加卡片 → 更新游标。  
4. **拉取好友圈（首屏）**：校验好友 wxid 非空 → 非追加模式调用好友列表接口 → 重置好友游标并记录 wxid → 清空 feed → 渲染。  
5. **好友圈下一页**：取 wxid = 输入框 trim 或好友游标中的 wxid → 追加模式调用 → 追加渲染 → 更新游标。  
6. **卡片点赞**：校验 snsId 与发布者用户名 → 组装 like 请求 → 日志 + 成功 Toast。  
7. **卡片私聊**：写全局锁定目标 → 跳转消息模块。  
8. **发布文本/链接/转发**：校验必填 → 单次 POST。  
9. **发布图文/视频**：先上传 POST → 校验成功与载荷形状 → 再发送 POST。  
10. **互动区点赞/取消**：与卡片共用 like 请求逻辑，`operType` 区分。  
11. **评论/详情/删除/下载视频/隐私项**：各自校验后 POST。  
12. **清空日志**：清空模块日志容器。

## C. 生产级工程质量要求

### C.1 防封控 / 限流与体验

- 翻页与刷新：**禁止**无间隔自动连打；用户点击驱动；可选加入最短间隔或并发互斥（同 feed 仅一条 in-flight）。  
- 卡片外链图片：默认 `lazy` + `no-referrer`；**须**限制缩略图数量上限，避免超大 XML 导致正则灾难（可设最大扫描长度或超时）。  
- 大整数 `snsId`：**禁止**静默丢精度；必须实现第 5 节规则并有单测。

### C.2 异步解耦

- 上传再发送：**顺序** `await`，第二步失败须有明确 Toast，且日志分别记录两步。  
- 单条卡片渲染：`try/catch` 隔离；不得因一条数据坏整张表。  
- 路由/会话事件监听：**防抖合并**刷新辅助文案（可选 `requestAnimationFrame`），避免风暴。

### C.3 全链路日志

- 每次 `apiPost`：**成功写完整响应信封**；失败写异常与请求体（令牌脱敏）。  
- 与全局审计日志双写时避免重复明文令牌。  
- 支持清空、导出（导出须脱敏）。

### C.4 安全与合规

- `snsXml` 可能含大量文本：日志展示应截断或折叠；**禁止**将用户粘贴的 XML 直接 `innerHTML` 渲染（卡片展示用 `textContent` 展示解析后的纯文案）。  
- JSON 语法高亮若用 `innerHTML`，必须转义。

### C.5 测试

- 表驱动：`snsIdForApi` 边界；列表键 `snsList`/`list` 兼容；翻页游标在成功后才更新；上传失败不调用发送。

## 4. 资料展示与快照

### 4.1 拉取资料

- **路径**：`/personal/getProfile`  
- **正文**：至少包含 `proxyIp` 键，值可为空串（与文档示例对齐）；设备标识走合并规则。  
- **成功**：`ret === 200` 且 `data` 为对象 → 进入「渲染资料卡片」流程。  
- **失败**：Toast 业务 `msg` 或默认文案；写日志。

### 4.2 渲染资料卡片

- **内存**：保存「最近一次成功资料载荷」引用供后续回填与闸门逻辑。  
- **快照持久化**：若设备标识非空且载荷为对象，则写入本地快照存储：**设备标识 + 完整载荷**（实现须限制体积或字段子集若担心配额）。  
- **UI**：展示头像（大图 URL 优先于小图）、昵称、wxid、微信号（别名）、地区（国家/省/市拼接）、签名、手机；无数据时显示占位符。  
- **表单回填**：将载荷中的可编辑字段写入左侧表单：昵称、国家、省、市、签名；性别为数值 **1/2** 时下拉框须用字符串 `'1'|'2'` 对齐。  
- **载荷非法或缺失**：清除快照；显示「空状态」；隐藏详情卡片容器。

### 4.3 路由进入时的冷启动顺序

当用户导航到「个人信息」路由时：

1. 若无设备标识 → 结束（不请求）。  
2. 若内存中尚无资料载荷 → 尝试读取快照：若快照中的设备标识与当前会话设备标识一致且含 `data` 对象 → **先渲染卡片**（可标记为快照数据）。  
3. **自动拉取闸门**：若本会话已对当前设备标识执行过自动拉取（内存标记或会话存储命中）→ **不再**自动请求；用户需手动点「获取个人资料」刷新。  
4. 否则：设置闸门为已拉取、写入会话存储、调用拉取资料流程。

首次打开页面若已处于该路由，须在初始化阶段用**微任务或等价**触发一次与「路由进入」相同的逻辑，避免仅依赖哈希变更事件。

- 缺少设备标识而取消请求：记一条本地说明（无需 HTTP）。  
- 导出与复制：令牌脱敏。

### C.4 安全

- 设备列表 HTML 拼接：**必须**对设备名、uuid、类型等转义。  
- 禁止将用户输入的 URL 或签名直接插入 `innerHTML` 而不转义。

- 单测：`sex` 仅在非空下拉时出现在 JSON；闸门在同 appId 下不重复自动请求；快照 appId 不一致不应用。

> 从「分页同步列表 → 卡片聚合展示 → 单条拉取 XML 并解析摘要 → 标记删除 → 将收藏摘要转发到当前聊天目标（跨模块发文本）→ 全链路日志」控制台行为抽象；不绑定任何源码标识符、UI 框架或存储 API 名称。

---

## 1. 目的与范围

**目的**：在已具备 **API 令牌** 与 **会话级设备标识** 的前提下，调用网关收藏域接口完成：增量同步收藏列表、按游标翻页、按收藏主键拉取详情 XML、删除收藏，并将某条收藏的**可读摘要**作为一条文本消息发送给当前锁定的聊天对象。

**范围**：三个核心接口——同步、取详情、删除；以及**可选联动**消息域「发送文本」接口（仅本模块的「发送给当前目标」能力使用）。  
**范围外**：收藏二进制本体落盘、非文本类原样转发（当前实现为摘要文本转发，产品若需原样转发须另附规格）。

---

## 2. 术语

| 术语 | 含义 |
|------|------|
| 业务信封 | 典型 `{ ret, msg, data }`；`ret === 200` 表示业务成功（以部署文档为准）。 |
| 同步游标 | 字符串 `syncKey`；首屏同步传空串；下一页传**上一次成功同步响应**返回的 `syncKey`；无游标则不得请求下一页。 |
| 收藏主键 | 整型 `favId`；列表合并与详情/删除均以该键唯一定位。 |
| 列表行 | 同步接口 `data.list` 中的元素，至少含 `favId`；可含 `type`、`flag`、`updateTime` 等（以文档为准）。 |
| 详情载荷 | `getContent` 成功时 `data` 内字段；须含可解析的 `content`（XML 字符串）及可选 `flag`、`updateTime`。 |
| 删除标记 | 文档约定 `flag === 1` 表示记录已删除；客户端在删除成功后**本地标记**该行，UI 展示「已删除」徽标。 |
| 解析缓存 | 将某 `favId` 从 XML 解析出的摘要结构：`desc`、`fromUsr`、`snippet`（短摘要，用于卡片与转发拼装）。 |
| 当前发送目标 | 全局会话中的聊天对象 wxid（及展示名）；与通讯录/消息模块共用。 |

## 3. 客户端内存模型（概念）

1. **收藏索引**：从主键到「列表行对象」的映射；同一主键后写覆盖前写。  
2. **解析缓存**：从主键到「摘要结构」的映射；在成功拉取详情或成功为发送而拉取详情后更新。  
3. **同步游标变量**：保存最近一次成功同步返回的 `syncKey` 字符串；首屏前可为空。

**不要求**在页面刷新后恢复上述内存（除非产品另要求持久化列表）；刷新后用户需重新同步首屏。

---

## 4. 同步列表与翻页

### 4.1 首屏同步

- **路径**：`/favor/sync`  
- **正文**：`syncKey` 为空串 `''`。  
- **成功**：`ret === 200` 且 `data` 存在。  
- **客户端动作**：
  1. **清空**收藏索引与解析缓存（全新同步）。  
  2. 将 `data.list` 数组合并进索引（跳过无 `favId` 的项；主键转整数）。  
  3. 将 `data.syncKey` 若为字符串则写入同步游标变量，否则写空串。  
  4. 刷新 UI 提示中的「当前 syncKey」文案；重绘卡片列表；Toast 成功。

### 4.2 下一页同步

- **路径**：同上 `/favor/sync`  
- **正文**：`syncKey` 为当前游标变量。  
- **前置**：若当前游标为空 → **禁止**请求，Toast 提示须先完成首屏同步。  
- **成功**：**不清空**索引与解析缓存；仅合并本页 `list`；更新游标；重绘；Toast。

### 4.3 失败

若 `ret !== 200` 或缺少 `data`：不更新游标与列表（与当前参考一致：静默 return，依赖日志与可选 Toast——传输失败时已有 Toast）。

---

## 5. 列表合并与排序展示

- **合并**：遍历同步返回的 `list`，对每项若存在合法主键则 `索引[主键] = { ...旧行, ...新行, favId: 主键 }`（合并策略：新字段覆盖旧字段）。  
- **排序**：卡片展示顺序为按 `updateTime` 数值**降序**；缺失或非数字视为 0。  
- **空列表**：展示引导文案，提示用户先执行首屏同步。

---

## 6. 获取详情（单条）

- **路径**：`/favor/getContent`  
- **正文**：`favId` 为整数（来自输入框解析 `parseInt`，无效则禁止请求并提示）。  
- **成功**：若 `data.content` 为字符串，则走 **XML 安全解析**（见第 7 节）写入解析缓存。  
- **索引补全**：若索引中尚不存在该主键，则插入**最小行**：从 XML 中正则解析 `<favitem type="数字">` 得到类型；`flag`、`updateTime` 取自详情载荷；若 XML 无类型则类型为 0。若已存在则合并更新：`type` 以 XML 解析成功值覆盖否则保留旧值；`flag`/`updateTime` 以新值覆盖若存在。  
- **UI**：重绘卡片；Toast 成功。

---

## 7. XML 摘要解析（中立算法）

**输出结构**：`desc`（描述）、`fromUsr`（来源用户标识）、`snippet`（短摘要）。

**步骤**：

1. 空输入 → 返回三字段空串，`snippet` 最终为「无摘要」类占位。  
2. 尝试 DOM 解析：若无 `parsererror`，读取 `desc` 元素文本；读取 `fromusr` / `fromUsr` / `FromUsr`（大小写兼容）文本。  
3. 若 `desc` 仍空：正则截取 `<desc>...</desc>` 内层并做类 XML 实体反转义（CDATA、`&lt;` 等）。  
4. 若 `fromUsr` 仍空：正则截取 `<fromusr>...</fromusr>` 内层并反转义。  
5. `snippet`：优先 `desc`；否则取原始 XML 去空白压缩后截取前 **160** 字符；再否则固定占位串。

**类型探测**：用正则匹配 `<favitem ... type="(\d+)"` 得到整数类型，供缺失列表类型时的补全。

**类型展示字典**：将数值类型映射为中文可读标签（未知类型显示「类型 n」）；字典须可配置并与产品文档对齐。

---

## 8. 删除收藏

- **路径**：`/favor/delete`  
- **正文**：`favId` 整数。  
- **UX**：须**二次确认**弹窗，文案包含目标 `favId`。  
- **成功**：`ret === 200` → 若索引中存在该行，则**就地**将 `flag` 置为 **1**（不强制从索引移除，以便展示已删状态）；重绘；Toast。

---

## 9. 「发送给当前目标」（跨模块）

**前置**：全局当前发送目标的 wxid 非空；否则 Toast 提示先在通讯录等模块锁定目标。

**步骤**：

1. 调用 `/favor/getContent` 拉取该 `favId` 的详情（与按钮「获取详情」同源）。  
2. 解析 `content` XML 得到摘要结构；若有 `desc` 或 `fromUsr` 则写回解析缓存并重绘卡片。  
3. 组装**纯文本**正文多行字符串，包含但不限于：固定标题行、`favId`、类型中文、来源行（若有）、空行、描述或 `snippet` 或「无文本描述」占位。  
4. 类型标签：优先使用列表行中的类型字段；否则使用 XML 探测类型；再否则 0。  
5. 调用消息域 `/message/postText`，正文含 `toWxid` 为当前目标、`content` 为上述文本，**长度截断至 8000 字符**（与当前实现一致，防超长）。  
6. 若发送业务 `ret === 200`，Toast 成功提示。

**日志**：两步请求均须记入模块日志（与全站 `apiPost` 行为一致）。

---

## 10. 卡片渲染与安全

- 每条卡片展示：`favId`、类型中文、来源好友（来自解析缓存或「—」）、收藏时间（`updateTime` 支持秒/毫秒时间戳启发式）、内容描述行（解析缓存优先）。  
- **`flag === 1`**：在标题区附加「已删除」视觉标记（文档语义）。  
- **「发送给当前目标」**按钮：每条卡片一个，携带该条 `favId` 与列表类型。  
- **HTML 安全**：卡片模板中凡插入用户或接口来源字符串，**必须**转义后再进入 DOM（防 XSS）。

---

## 11. 当前发送目标展示

- 监听全局会话变更事件：当存在目标 wxid 时，展示「当前发送目标」行；展示名优先通讯录缓存反查，其次会话展示名；格式可为 `展示名（wxid）` 或仅 wxid。

---

## 12. 日志

- 每次 POST：记录路径、合并设备标识后的请求体、响应信封或异常；失败 Toast 含路径短后缀。  
- 提供清空日志能力。

## A. 业务流转逻辑（Workflow）

1. **初始化**：更新 syncKey 提示；渲染空列表与发送目标提示；绑定按钮与全局会话监听。

3. **下一页同步**：校验本地游标非空 → 请求 → 成功则合并不清空 → 更新游标 → 重绘。  
4. **获取详情**：解析输入 favId → 请求 getContent → 解析 XML 写缓存 → 更新或插入索引行 → 重绘。  
5. **删除**：解析 favId → 确认框 → delete → 成功则标记 flag=1 → 重绘。  
6. **发送给当前目标**：校验全局目标 wxid → getContent → 解析 → 组装文本 → postText（≤8000）→ Toast 视 ret。  
7. **清空日志**：清空日志容器。

## C. 生产级工程质量要求

### C.1 防封控 / 体验

- 下一页无游标时**禁止**空游标请求；须明确 Toast。  
- 文本转发 **8000** 字符截断须在 README 说明可能丢失尾部信息。  
- 同步按钮可 Loading 互斥（参考未强制；**建议**首屏与翻页互斥防止双请求）。

### C.2 异步解耦

- `getContent` → `postText` 须顺序 `await`；第二步失败仍应有 getContent 日志。  
- 卡片渲染循环内单条异常不得阻断整表（try/catch 单卡）。

### C.3 全链路日志

- 每次 `apiPost` 成功/失败均写模块日志；令牌脱敏。  
- 解析失败不抛到未捕获：写空摘要即可。

### C.4 安全

- 卡片 `innerHTML` 拼接须 **escapeHtml**；描述行来自 XML 解析后仍须转义展示。

### C.5 测试

- 单测：游标为空拒绝下一页；首屏清空缓存；删除仅改 flag；`snippet` 160 截断；`postText` 长度截断。  
- 契约：`ret!==200` 不更新游标（sync）；不更新索引（getContent 失败）。

## A. 业务流转逻辑（Workflow）

1. **初始化**：若当前路由已是标签页，执行一次 wxid 预填；渲染列表（空则提示）；刷新辅助展示；绑定事件与 `hashchange`、`state-changed`。  
2. **用户点击获取列表**：POST `/label/list` → 日志 → 成功则存 `labelList` 并重绘卡片。  
3. **用户新增标签**：校验名称 → POST `/label/add` → 日志 → 成功则静默刷新列表。  
4. **用户删除标签（卡片）**：确认框 → POST `/label/delete`，`labelIds` 为**该标签 id 的字符串** → 日志 → 成功则静默刷新列表。  
5. **用户提交修改成员**：解析 `wxIds` 数组与 `labelIds` 字符串 → 校验非空 → POST `/label/modifyMemberList` → 日志 → 成功 Toast。  
6. **用户复制 labelId**：剪贴板 API 或降级方案 → Toast。  
7. **清空日志**：清空日志区。

## C. 生产级工程质量要求

### C.1 防封控 / 体验

- 新增/删除/修改提交期间建议 **按钮 Loading 互斥**（参考实现未统一；**本提示词建议**对会触发写操作的按钮禁用防连点）。  
- `labelIds` 为全量：README 须强调误传子集的后果（以网关文档为准）。

### C.2 异步解耦

- 删除成功后 `await` 列表刷新再结束交互，避免卡片仍显示已删项。  
- 剪贴板失败须有用户可见反馈。

### C.3 全链路日志

- 每次 `apiPost` 写模块日志；令牌脱敏。  
- 传输异常：写错误行 + Toast。

### C.4 安全

- 卡片与弹窗文案中 `labelName` 须转义；确认框拼接用户输入时注意注入换行等（使用转义或模板安全策略）。

### C.5 测试

- 单测：`parseWxIdsInput` 对中英文逗号、空白；`wxIds` 为空拒绝；删除 `labelIds` 为字符串类型。  
- 集成：删除成功后列表长度减一；add 成功后列表含新名。

三、 工程质量与安全红线 (Constraints)
异步解耦：主业务必须与 Webhook / 上游 HTTP 回调 解耦；回调仅入队，由异步 Worker 执行写操作（发布、点赞、评论、私信、扫码登录等）；禁止在 Webhook 同步线程内串联全部 Finder 接口。

容错机制：所有网络请求必须包含 try-catch（或语言等价）；解析 JSON 失败、超时、ret≠200、HTTP 非 2xx 均须拦截并记录；绝不允许主进程崩溃；ret=500 且带 data.code 的路径须单独分支记录。

随机延迟：每次业务接口调用间隙必须插入 Random Delay（默认 2～5 秒，可配置）；搜索翻页、异步查询轮询、批量互动禁止固定周期连打；轮询间隔须带随机抖动并设上限。

结构化日志：每个步骤打印 [ISO8601时间戳] [动作中文] [Path] [ret或HTTP] [结果摘要]；VideosApi-token、完整 cookie 搜索串、长 Base64 脱敏或截断；失败须含请求关键键名（不含密钥）。

补充红线：POST /finder/search 的 searchID 字段名以响应为准（文档示例为 searchID）；跨模块接口（/message/*、/sns/*）须单独客户端或路由前缀配置，避免错误拼接 Base；大文件发布必须走文档规定的异步 CDN 链路；严禁伪造扫码 qrUrl/qrContent。
