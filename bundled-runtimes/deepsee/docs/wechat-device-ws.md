# 新微信设备与自动回复

接入配置位于“功能设置 → 微信网关”：选择设备 key 协议，填写 API 地址和设备 key，开启网关、发送与 WS 监听。key 模式不需要 AppId。设备 key 仅保存到本地运行配置，不写入源码或消息元数据。

## 链路

- 收消息：`GET /ws/GetSyncMsg?key=...`，断线重连，支持 `message` JSON 封装及批量消息。
- 建连时从 `/other/GetRedisSyncMsg` 补取一次缓存，不持续轮询；使用相同去重与回复时效规则。
- 生成回复：复用现有触发规则和自动回复事务，使用 MiniMax-M3，不引入第二条 Agent 执行链路。
- 发文本：`POST /message/SendTextMessage?key=...`。
- 发卡片：`POST /message/SendAppMessage?key=...`。
- 状态：`GET /api/wechat-gateway/device-status`；设备健康：`GET /api/wechat-gateway/device-health`。

上游 Swagger 只提供 WS 接收端点，没有 WS 发送协议，因此发送使用文档中的 HTTP API。

## 行为

- 保留现有触发设置：私聊 `ai` 前缀，群聊按已有 @ / 前缀规则；不默认回复全部消息。
- 复用消息去重与发送事务，自身消息不触发回复；超过五分钟或缺少时间的消息仅入库。
- 上游成功响应可能含 `Success=false`，依据 `Code`、`isSendSuccess`、嵌套 `base_response.ret` 和逐条发送结果判断，不盲目重发。
- 提取嵌套 `chat_send_ret_list` 的 `newMsgId`，用于发送记录和自身回声识别。
- 通讯录：分页调用 `/friend/GetContactList`，再通过 `/friend/GetContactDetailsList` 获取备注、昵称与群名；兼容 `str` 字段封装，微信号 `alias` 不作为备注。
- 消息显示优先级为备注、昵称、ID；群聊使用最新群名。历史消息动态读取本地通讯录，底层发送目标 ID 不变。
- 同步时补齐已接收消息里的未保存群和群成员名称；标签接口不可用时保留原标签，不阻塞名称同步。详情缺失不覆盖已知名称。
- 企业微信成员通过原始群上下文调用 `/qy/QWContact`；大批详情返回空项时，对消息关联对象进行小批量补取。
- 新设备尚未适配图片、文件接口，旧接口调用明确拒绝，不混用不同协议。
