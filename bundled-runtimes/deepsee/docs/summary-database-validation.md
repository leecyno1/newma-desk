# 摘要数据库验证报告

## 概述

本次更新创建了摘要数据库功能，将微信和邮件消息的摘要（summary字段）提取到独立的JSON文件中，作为备选数据源。这样可以显著节省token，因为摘要通常比原文短很多。

## 已实现的改进

### 1. 会议路演信息
- ✅ **修改完成**：主题要点严格只使用 `summary` 字段，去除 `ai:` 前缀
- ✅ **不再fallback**：如果没有摘要，则跳过该消息，不使用 `content` 作为后备
- **位置**：`app/routers/ai.py::_extract_meetings()`

### 2. 市场观点总揽
- ✅ **提示词优化**：要求像智能体一样通览全文，理解大段文字的核心意义，概括主旨，不要提取泛用名词
- ✅ **数据覆盖改进**：如果筛选后消息少于30%，则使用全部消息；增加limit从320到400确保覆盖更多消息
- ✅ **摘要优先**：`_compact` 函数优先使用摘要字段，无摘要时才使用截断的正文
- **位置**：
  - 提示词：`app/services/llm_client.py::DEFAULT_MODULE_PROMPTS["market"]`
  - 数据覆盖：`app/routers/ai.py::_run_summary_local()`

### 3. 新闻舆情监测
- ✅ **提示词优化**：要求通览全文，理解每篇新闻的核心意思，用概括性语言总结要点，严禁直接复制新闻标题或内容
- **位置**：`app/services/llm_client.py::DEFAULT_MODULE_PROMPTS["newswatch"]`

### 4. 高评分联系人
- ✅ **评分阈值**：只取评分>=60分的联系人（之前没有明确阈值）
- ✅ **使用摘要**：优先使用消息的 `summary` 字段，不再直接使用 `content`
- ✅ **提示词优化**：明确要求使用摘要字段进行总结
- **位置**：
  - 筛选逻辑：`app/routers/ai.py::_run_summary_local()` 
  - 提示词：`app/services/llm_client.py::DEFAULT_MODULE_PROMPTS["contacts"]`

### 5. 摘要数据库
- ✅ **创建功能**：在生成AI总结时，自动创建摘要数据库JSON文件
- ✅ **文件位置**：`data/datasets/summaries_{period}_{snapshot_id}.json`
- ✅ **数据结构**：
  ```json
  {
    "period": "1day",
    "snapshot_id": 123,
    "counts": {
      "wechat": 100,
      "email": 50
    },
    "wechat_summaries": [
      {
        "id": 1,
        "time": "2025-01-01T10:00:00",
        "sender": "user1",
        "summary": "摘要内容（已去除ai:前缀）",
        "tone": "positive",
        "category": "观点"
      }
    ],
    "email_summaries": [...]
  }
  ```
- **位置**：`app/routers/ai.py::summary()`

## 摘要数据库适用性分析

### ✅ **完全适用**（推荐使用摘要数据库）

1. **市场观点总揽** (`market`)
   - **原因**：摘要已经包含了核心观点和要点，大模型可以从摘要中提取主题和趋势
   - **节省token**：预计节省60-80%的token
   - **质量影响**：低，因为摘要本身就是对观点的概括

2. **高评分联系人** (`contacts`)
   - **原因**：摘要已经概括了联系人的核心观点，非常适合用于联系人总结
   - **节省token**：预计节省70-85%的token
   - **质量影响**：低，因为只需要概括性信息

3. **会议路演信息** (`meetings`)
   - **原因**：会议信息已经在摘要中提取了要点，主题列直接使用摘要
   - **节省token**：预计节省50-70%的token
   - **质量影响**：无，因为已经强制使用摘要

### ⚠️ **部分适用**（需要验证）

1. **分歧观点分析** (`counter`)
   - **原因**：需要对比正负面观点，摘要可能保留足够信息，但需要验证是否能准确识别分歧
   - **建议**：先用摘要数据库测试，如果质量下降则回退到原文
   - **节省token**：预计节省60-75%的token

### ❌ **不适用**（建议继续使用原文）

1. **新闻舆情监测** (`newswatch`)
   - **原因**：新闻本身来自外部源，不是消息摘要，需要完整内容进行分析
   - **注意**：新闻模块不读取消息，而是直接读取新闻源

2. **自媒体舆情监测** (`socialwatch`)
   - **原因**：同新闻模块，需要完整内容

## 使用摘要数据库的方法

### 当前实现

当前代码已经在 `_compact()` 函数中实现了摘要优先策略：
- 如果消息有 `summary` 字段，优先使用摘要
- 如果没有摘要，才使用截断的正文（前200字符）
- 这样已经可以节省大量token

### 完全使用摘要数据库（可选实现）

如果需要完全从摘要数据库读取，可以修改 `_run_summary_local()` 函数：

```python
# 如果提供了summary_db_path，且模块适用摘要数据库，则从摘要数据库读取
if summary_db_path and module_key in ["market", "contacts", "meetings"]:
    with open(summary_db_path, 'r', encoding='utf-8') as f:
        summary_db = json.load(f)
    # 使用摘要数据库的数据
    module_payload["messages"] = summary_db.get("wechat_summaries", []) + summary_db.get("email_summaries", [])
```
