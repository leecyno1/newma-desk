# 四平台发布包装

以 `configs/publish/platform_content_rules.json` 为机器可读准则；平台规则会变化，长度上限和活动列表在发布当天重新核验。

## 通用顺序

1. 冻结主视频与事实口径。
2. 为每个平台独立生成标题、主题文案、标签、封面和平台字段。
3. 把每个内容版本路由到明确的逻辑账号与账号槽。
4. 实时发现活动，只保留标题与内容直接相关的候选。
5. 生成 `channel_pack.json`，运行表单预检和上传 Dry Run。
6. 运行 `publish_accounts.py --check-auth`；主上传器登录态全部为 `valid` 后，获取当前任务/Campaign 的一次发布授权。
7. 发布后回收正式链接或草稿 ID，并运行 Publish Guard。

## 平台包装

### 小红书

- 标题：结论先行，优先 18 字以内。
- 文案：第一人称结论 + 三条证据 + 讨论问题；避免直接复制长口播稿。
- 标签：4–8 个，混合主题词、行业词和受众词。
- 封面：默认 1080×1440；来源图表必须完整显示，不裁掉标题、坐标、图例或数字。
- 活动：进入创作中心实时查看，只参加与标题和内容直接吻合的活动。

### 抖音

- 标题：三秒钩子 + 核心结论，优先 30 字以内。
- 文案：钩子 + 证据链 + 结论，避免冗长分段。
- 标签：3–6 个，优先内容相关性，不堆热词。
- 封面：默认 1080×1920；方形视频可原画质直传，必要时另做模糊补边衍生版。
- 活动：优先用 OpenCLI 实时查询；只有编辑确认后才写入 `activity_selected`。
- 声明：只传入用户或编辑明确批准的平台原文，禁止推断“原创”“AI生成”等声明。

### B站

- 标题：允许更完整地表达问题、证据和结论，优先 60 字以内。
- 简介：章节摘要 + 数据来源说明 + 风险提示。
- 标签：5–10 个；分类 `tid` 必须明确。
- 封面：默认 1920×1080，构图兼顾移动端缩略图可读性。
- 活动/合集：只选择当前可见且直接相关的官方话题或合集。

### 视频号

- 标题：口语化核心结论，优先 28 字以内；同时生成短标题。
- 文案：通俗结论 + 分享动机，避免过多专业缩写。
- 标签：3–6 个。
- 封面：默认 1080×1440，并保留竖版缩略图字段。
- 活动：通过视频号助手的当前页面实时复核。

## 账号与 Cookie

- `publisher-a` / `publisher-b` 是跨平台逻辑账号；真实平台昵称不写入 Git。
- 每个平台用稳定的 `slot-1` / `slot-2` 与命名浏览器 Profile 隔离登录态。
- 浏览器 Profile 位于 `~/Library/Application Support/NewmaPublishProfiles/`。
- CLI 会话位于 `~/Library/Application Support/NewmaPublishSessions/social-auto-upload/cookies/`。
- 不读取、不复制、不导出 Cookie 内容。首次登录或失效后只打开对应命名 Profile/CLI headed 登录一次。
- 有头浏览器使用附属屏幕优先的固定小窗策略，禁止全屏和最大化；附属屏缺失时降级到主屏边缘小窗。

## 活动与最终确认

- 活动名不得从旧记录、标题或模型常识中虚构。
- 活动候选为空不是错误，应保留 `live_discovery_required`。
- Dry Run 成功不代表已登录，也不代表已发布。
- `account_auth_status != valid` 时禁止 Campaign 批量确认执行。
- 用户已明确要求发布时，视为当前任务/Campaign 的整体授权；授权范围内的最终发布点击、原创/AI 声明、协议和封面确认弹窗自动处理。
- 已同步到当前电脑的用户自有账号一次性验证码，只在能匹配当前平台、账号和时间时自动填写一次；不得保存、记录或复述验证码。
- 图形验证码、滑块、账号风险审核或无法匹配的一次性验证码仍是硬停项，禁止循环尝试。
- 发布命令返回 0 后仍保持 `needs_manual_verification`，直至回收平台 URL、稿件 ID 或可核验草稿 ID。
