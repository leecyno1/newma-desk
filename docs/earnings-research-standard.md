## 目标

财报研究 Mod 把财报前与财报后的工作放进同一份结构化底稿：

```text
最新报告期与来源核验
        ↓
内部预期 / 一致预期 / 公司特定指标
        ↓
实际结果与 Beat / Miss
        ↓
差异驱动、利润率、经营指标与指引变化
        ↓
预测修订与投资逻辑影响
        ↓
下一期验证条件和数据缺口
```

页面只记录事实、预期、研究假设和逻辑影响，不保存评级、目标价、买卖动作或财报后的价格反应预测。

## 数据合同

共享 Schema 位于 `packages/contracts/src/earnings.ts`。根对象包含：

- 证券身份、市场、币种；
- `preview / reported` 模式；
- 报告期、期末日、披露日和披露时段；
- 最新报告期核验状态和主要来源；
- 财务指标与公司特定经营指标；
- 实际、内部预期、一致预期及金额、百分比或基点差异；
- 当前与上次管理层指引；
- 高于、符合、低于预期三种条件情景；
- 旧预测、新预测和修订原因；
- 对 Thesis 支柱的 `strengthened / weakened / neutral / invalidated` 影响；
- 来源材料、截至日期和数据缺口。

## 来源与截至日期

1. 使用数据前先验证最新报告期，不把模型记忆当成财报事实。
2. 公司财报、交易所或监管披露和管理层材料优先于新闻摘要。
3. 一致预期必须标注来源和快照日期；缺少时保持空值，不静默估算。
4. 财报差异需要检查会计口径、基数、一次性项目、季节性、并购和汇率等影响。
5. 当前指引必须与上次指引使用相同口径比较；口径变化本身也要记录。

## 数据与存储复用

不新增数据库、后端服务或端口。2026-09-16 起自动回填范围以下文修订为准。可复用的研究基础包括：

- `equityResearch`：跨市场证券身份、证据账本、来源诊断和缺口；

- Desk-managed Storage：保存用户录入的预期、指引、修订和逻辑影响。

存储配置：

- namespace：`earnings-workbench`
- document key：`workbooks`
- scope：`user-workspace`
- schema version：`1`
- local fallback：`newma-desk.earnings-workbench.v1`

## Agent Context

页面向统一 Newma Agent 发布当前证券、报告期、模式、来源核验、预期差、经营指标、指引、条件情景、预测修订、Thesis 影响和数据缺口。

Agent 可以继续查询页面之外的数据，但新增内容必须：

- 给出来源和截至日期；
- 区分财报事实、管理层表述、市场一致预期和研究假设；
- 说明它如何改变经营假设、预测或 Thesis 支柱；
- 不直接转换为买卖、仓位或价格反应建议。

长篇 DOCX 财报前瞻或财报复盘报告属于可选 Agent 任务，不进入 Mod 运行时代码。

## 接入要求

其他项目接入本标准时应：

1. 使用共享合同或提供无损映射；
2. 保留稳定的 workbook、metric、source、revision 和 thesis-impact ID；
3. 声明 `storage.read / storage.write`，由 Desk 分配 namespace；
4. 将证券与报告期放进 Agent Context；
5. 显式展示未核验、来源失败和缺失一致预期；
6. 不在 Mod 内重复实现 Agent、模型设置、聊天记录或独立数据库。

## 2026-09-16：财务证据刷新修订

- 自动回填仅使用现有 `financials` 接口的 A 股人民币同花顺财务摘要。研究快照、公告/新闻列表不再充当财务数字的替代来源；港美股可保留人工底稿，但本轮不自动回填。没有执行或安装外部项目。
- 金额根据明确的元/万/亿单位转换，不按数值大小猜测。空串、占位符、区间及无单位金额保持缺失；百分比与每股金额依接口字段口径解析。不将空值当零。
- 候选必须有有效且不晚于采集日的报告期。已有底稿须确认期末；不同报告期不覆盖，另建底稿。不用 Evidence Ledger 的 `asOf` 代替报告期，也不用采集日补来源日期或披露日。
- 每个成功回填指标保存 `periodEnd`、`reportedCurrency`、`reportedOrigin=provider` 及对应摘要来源 ID。来源保存 `periodEnd` 和 `retrievedAt`，未知 `asOf` 可省略。共享 v1 合同新增可选字段，旧记录仍兼容。手改实际值转为 manual，清除原自动来源引用，避免将人工数字归给接口。
- 刷新先显示候选表，确认才进入草稿；取消不变更。缺值保留原指标及其来源，并列明未更新。内部预期、一致预期、指引和研究判断不变。刷新已保存底稿后采用为新 ID，保存不覆盖原底稿。已有财务或预期时锁定证券、币种及已确认期末，跨证券事件不混入现有研究。
- 接口返回数据只标部分核验，`latestPeriodChecked=false`。原始公告披露日及最新报告期尚未独立核验。旧 verified 标记在存储中保留；页面标为历史待复核，Agent 使用审慎解释，不发布 fresh。
- Agent 区分已采用草稿与 `candidateEvidence`，后者带“尚未采用”状态。工作区写入成功才提示已保存到 Desk；仅浏览器保存明确提示未同步；两边失败保留草稿并报错。

参考 OpenBB 的单一数据出口、EdgarTools 的披露与财务证据绑定思想；不引入其运行时，也不把美股 EDGAR 能力声称为 A 股支持。真实数据源可用性、公告原文核验、一致预期供应商及季报/累计/TTM 可比口径仍需后续深化。本批不等于整个公司栏目验收完成。

## 2026-09-18：公告支持的人工数值修订

- 复用已关联公告摘录，人工填写拟采用值和理由，先比较当前底稿、候选值及差额，再逐项确认。不是自动抽取的原报告/更正报告对照；不从标题推断替代关系，不自动验证摘录中的数值。

- 来源保存修订前后值、理由、采用时间、公告摘录及原数值来源 ID；被修订记录引用的来源不能直接取消。后续手改实际值清除当前来源引用，但历史记录仍保留，并明确不代表当前仍采用该值。
- Agent 分开接收尚未采用的 `correctionCandidate`、当前实际值和历史采用记录。使用原 Desk/本机保存链路，可选字段兼容旧底稿；不增加独立存储或 Agent 内核。

## 2026-09-18：PDF 物理页阅读与摘录定位

- 比较 [pypdf](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)、[pdfplumber](https://github.com/jsvine/pdfplumber) 与 [PDF.js](https://github.com/mozilla/pdf.js) 后，本批采用 pypdf（BSD-3-Clause）逐页文字提取。依赖同时写入 Research 独立环境与集成环境清单；不增加 OCR 或浏览器阅读器依赖。
- `/announcement-pdf-page` 仅接受证券、公告编号和物理页码，先复核公告所属证券，再读取数据源提供的固定 PDF 域名附件；不接受任意 URL、不跟随跳转。支持前后页和跳页，最多读取第 1000 页；单文件上限 20 MB。成功下载的文件在内存缓存 10 分钟、最多 4 份，翻页保留原下载时间，不冒充新鲜数据。
- PDF 物理页从 1 起且包括封面，不等同印刷页码。响应与摘录的 `contentOrigin=pdf-text`、`pdfPage`、`pdfPageCount` 明确区别于旧转录 `segment`；只读取当前页，不声称全文已读。空白页或无法提取文字的页面保留页号并显示缺口，不自动断言扫描件。
- PDF 摘录保存链接、页号、总页数和原文，沿用人工指标关联、数值修订与底稿保存流程。保存重载后可用 `#page=N` 链接返回原页（实际跳页取决于浏览器 PDF 阅读器），不保存或伪造表格坐标。关联不自动改财务值或提升核验状态。
- Agent 区分转录分段、PDF 当前页、无文字页与已保存摘录；切页/读取失败清理旧阅读内容，刷新后只保留已保存摘录。表格列序、单位、合并单元格仍须对照原页，尚未做结构化表格、区域高亮或 OCR。
- 实测公开公告 `AN202608141827994407` 首次提取到两页文件首页文字，并渲染原 PDF 核对；后续数据源曾返回网页校验脚本而非 PDF。系统拒绝将其解析为正文，明确提示来源失败；缓存不是绕过来源限制的方案，不保证数据源持续可用。

## 2026-09-20：财报问答不自动继承模组历史

- 财报研究的问答、批量分析使用已有 `memoryScope=task`。前端明确声明，任务网关对非 `module.edit` 的财报请求统一落实，包括旧客户端未填写或仍填写模组记忆的请求；其他模组和代码修改模式不变。
- 本地 CLI 不读取或追加 Desk 模组对话库；Hermes 连接创建本次会话，不读取或覆盖原模组会话映射。旧聊天、原会话与底稿均保留，不做清理或迁移。快速模型原本只接收本次问题及页面上下文，保持原路径。
- 侧栏明确提示“每次读取当前底稿，不继承旧对话。追问请写明具体问题”。这暂不提供同一底稿多轮记忆；“继续上面”等省略式追问需要用户补齐。该规则限制的是 Desk 自动注入的历史和会话复用，不承诺隔离外部 Agent 自己的全局记忆或用户主动引用的其他材料。
- search-first 参考 [OpenAI Agents SDK Sessions](https://github.com/openai/openai-agents-python/blob/main/docs/sessions/index.md) 关于会话自动保存并延续历史的设计，复用仓库现成的单次任务机制，不接入 SDK 或新建 Agent 内核。
- 验收：44 项网关/适配器测试、19 项 Copilot 测试、3 项页面验收及 Shell 构建通过。覆盖已有旧记录时不读取也不追加、远端新建两次不同会话且旧映射不变、页面历史可见但不随新请求发送。测试使用替代 CLI/上游响应，没有新增真实模型分析。确认无排队或运行中任务后，仅重启本地 API，健康检查通过。
