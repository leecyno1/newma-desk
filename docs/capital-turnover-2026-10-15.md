# 成交活跃度补齐 · 2026-10-15

## 问题与选择

旧 `/api/market/turnover-top` 实测 HTTP 200，但 stocks 为空，且旧 updated 是请求时间而不是行情日期。

本轮复用现有 Tushare 配置、交易日历和 CapitalHistoryStore，不添加行情 SDK、图表依赖或 Agent 内核。按 finance-data-router 与 search-first 的快速研究流程核对现有链路和官方字段。

- [Tushare 日线](https://tushare.pro/document/2?doc_id=27)：未复权，amount 单位为千元；入榜金额转元、展示转人民币亿元。
- `stock_basic` 仅用于名称和行业显示，当前在市目录不作为历史成分证据。
- 每页 4,000 条，最多 5 页；分页失败、重复或超过上限不发布部分结果为完整榜单。

## 实现

- `/api/capital-flow` 并行读取既有维度和新成交研究，生产路径不再调用旧成交榜；`refresh=true` 刷新日线及目录。
- 按交易日保存榜单、覆盖和交易所汇总，缓存 5 分钟。失败保留快照，但 current=false，旧 summary 不确认失败快照的前20成交额。
- 统一以昨日及以前最近交易日为目标，不提供盘中或当日盘后更新。
- 行情按同日证券代码去重。缺金额、冲突和错误日期会停止合计及集中度；缺失市场不补零。
- 页面新增样本成交额、前20成交额、前20占比、沪深北分布、来源说明；排行可进入个股资金研究，长榜单内部滚动。
- Agent 获得与页面相同的日期、样本范围、单位、榜单、缺口和是否为保留快照。不用旧无日期榜单填充缺失。

## 实测

2026-10-14：分页 4,000 + 1,563 条，5,563 个有效股票样本，名称全部匹配，无错误日期/金额缺失/冲突。

前20占该样本 9.07%。这不是净流入，也不构成活跃度偏高/偏低的判断。

## 验收及边界

后端覆盖单位、集中度分母、去重冲突、空值/零值、日期排除、分页、缓存与更新失败保留快照。浏览器覆盖页面/Agent一致、刷新失效标识、股票跳转、移动端及真实样本。

验收结果：前端编译成功，资金后端89项通过；浏览器43项中42项首次通过，1项在API重启期间因模块目录500失败，服务恢复后独立复测通过。真实桌面和移动端截图已人工查看。

仍未与交易所全市场统计及停牌清单独立对账，因此 universeVerified=false，不称全市场总成交额。历史成交基线和集中度变化尚未接入；本轮不添加缺乏历史依据的强弱标签。
