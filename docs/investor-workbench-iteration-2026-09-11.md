# Newma-Desk 全模组投资工作台迭代
日期：2026-09-11
状态：风控按用户要求暂停，真实组合业务验收待进行；2026-09-16 用户确认公司栏目首批财报研究开工。未开始交易模组。

## 1. 本轮约定

- 按“整体判断 → 单模组讨论 → 实现 → 验收 → 用户确认 → 下一模组”推进。
- 单模组开工前提交：投资问题、现状证据、外部参考、保留/合并/新增范围、数据条件、验收案例。
- 一次只改一个业务模组。必要的共用代码改动必须说明影响范围，并回归受影响页面。
- 不把服务存活、页面有内容、Agent 能回答或测试数量当作业务验收完成。
- 本地测试；不远程部署、不推送 Git，不启用真实交易或对外发布。
- 保留 Newma 挂载、本地 Agent CLI、独立 Copilot 三种使用方式。多 Agent 组织与协作规划仍由 Newma 任务统筹。
- 不安装或执行网上找到的项目。本轮只检索公开项目、官方文档和论文；实际引入依赖须在相应模组讨论时决定。

## 3. 投资人的核心使用链

研究线索 → 可核验证据 → 投资假设与反方意见 → 估值/收益风险 → 组合方案 → 决策 → 交易计划 → 执行账本 → 风险处置与复盘。

沿这条链检查每个页面：

1. 我要做什么判断，而不只是看什么图？
2. 相比上次，什么发生了变化？
3. 数字来自哪里，何时公开，当时是否可知？
4. 什么证据会推翻结论？
5. 产物如何保存、复核，并交给下一环节？

### 五项共用规则

- **对象一致**：证券、基金份额类别、币种、账户、行业分类、事件和研究档案有稳定身份；名称搜索不能改变资产类型。
- **证据一致**：区分统计期、公布时间、采集时间、历史版本；事实、计算、假设、推断分开。缺失不显示 0，未评估不显示正常。
- **产物一致**：优先复用已有账本和索引；交接使用来源 ID、版本、截至日期及范围，不复制另一套正文或持仓。
- **人和 Agent 一致**：所选对象、筛选、时间范围、正文、有效性和可操作范围一致；截图重开不能冒充当前窗口状态。
- **交互一致**：一个主标题、紧凑工具栏、清晰主表/主图、按需详情；主文字默认约 14–16px，辅助内容避免过小；画布、表格不强行塞成等大卡片。

风险、交易、发布、授权等操作必须与只读研究分开。不同账户、币种和数据完整度不能被一个总分掩盖。

| 量化（5） | 因子—回测—相关性骨架已有 | 数据/参数版本、样本外、滚动验证、交易成本、可交易性、退市样本、容量、失败实验归档 | 可复现且说明局限的实验账本 |
| 投决（8） | 讨论、报告、席位、工具已多；页面偏按引擎功能展开 | 核心围绕议题、证据包、反方、决议、条件、责任人与复核；席位/Skills/设置适度收进配置入口 | 决策记录，而不是一段多 Agent 对话 |
| 深瞳（11） | 渠道多，宜定位证据采集与整理层 | 原文定位、去重、实体/事件抽取、权限、隐私、来源可信性、与研究档案的引用交接；群发不混入只读研究 | 可授权、可引用的私人信息证据 |
| 创作（9） | 六阶段内容生产主线合理 | 引用研究版本、事实核验、人工编辑、发布前审校、状态回执、反馈归档；草稿不自动成为投资事实 | 可追溯发布成品和传播复盘 |
| 工作流（11） | 应承载跨栏目协作，不再复制业务页面 | 节点输入/输出、边参数、运行回放、失败恢复、审批、版本和产物溯源；模板态/运行态清楚分开 | 可恢复的执行过程与有来源的交付物；组织 Agent 规划交给 Newma |

### 优先理清的重叠

- 新闻与舆情 vs 深瞳新闻：公开市场情报 vs 多渠道私人/组织信息采集，共享引用，不共享访问权限。
- 催化剂日历 vs 政策日历 vs 日线时间轴：未来跨类事件 vs 政策生命周期 vs 已发生事件与价格复盘。
- 行业轮动 vs 行业与 ETF 轮动：分别明确资金视角和量价/策略视角，共用行业身份与来源。
- 配置评估 vs 基金归因 vs 交易复盘：组合收益来源 vs 基金策略贡献 vs 执行/决策偏差。
- 投委会 vs 工作流：投资决策业务 vs 通用协作与执行，不让二者各造一套 Agent 内核。
- 创作发布 vs 深瞳群发：内容交付 vs 信息触达；都须显式确认接收对象和最终内容。

## 5. 值得补充的能力，而非先增加一级菜单

### 优先补齐

1. **个人投资工作台**：自选、持仓变化、待核验事件、待复核论点、风险处置的汇总。复用现有对象，只作为首页/视图。
2. **研究到收益的复盘**：买入时的论点、估值假设、后续事实、仓位决策、执行成本、退出原因串起来。落在公司/交易/配置里。
3. **数据可用性说明**：每个结论展示数据覆盖、延迟、最后成功时间、替代来源及缺口。Provider 健康与业务证据完整度分开。
4. **投资目标与约束**：研究组合的基准、期限、币种、流动性要求、风险预算。先把“对谁而言更好”定义清楚。

### 第二阶段再考虑

债券/信用/利率曲线、商品/外汇、期权与对冲、海外基金。先按对应资产定义数据合同与验证案例，再放进现有栏目；不为“功能齐全”先建空页面。付费一致预期、逐笔/AIS、商业基金数据库等必须说明来源、预算与授权限制。

## 7. 每个模组的统一验收方式

每个模组建立一个精简验收包：当前范围、几个典型用户任务、样例数据和预期结果、实际执行结果、截图/导出物、已知限制。优先测试业务行为，不堆无关测试。

### 必过项目

1. **入口**：Desk 内嵌与独立打开；必要的桌面/窄屏布局；一级标题不重复。
2. **对象与阅读状态**：搜索、选择、筛选、切换、刷新、前进后退；跨页交接不串对象。
3. **数据**：正常、过期、部分缺失、完全缺失、源不可用；说明统计期/币种/单位。
4. **计算**：用能手工核算的小样例验证公式；涉及历史判断必须检查当时可知数据。
5. **持久化**：保存、关闭重开、更新、冲突或失败反馈；用户/工作区隔离。
6. **Agent**：当前提问使用当前页面证据，动作范围与实际权限一致。测试数据交接与模型最终回答必须分别记录。
7. **投资业务闭环**：本模块产物能进入下一环节；引用来源和版本仍可核对。
8. **失败恢复**：不可用时不会误报成功，不丢已保存结果，不自动执行下单、群发或发布。

### 验收结论

- **通过**：约定范围内典型与失败路径均有证据。
- **有条件通过**：非核心外部数据受限，界面与结论明确降级，并由用户接受范围。
- **未通过**：错数、误导状态、核心任务不可完成、保存/权限/交接失败。
- 没测过就是“待验收”，不给假精确完成度分数；本轮不评全系统生产级评分。
