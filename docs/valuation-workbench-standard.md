# Newma-Desk 预测与估值标准

Mod：`valuation-workbench`
合同：`newma-desk.valuation-workbench.v1`
存储：`valuation-workbench/models`
兼容级别：Level 3

## 1. 职责与边界

预测与估值 Mod 将财报研究、同业比较和投资逻辑中的可验证输入，整理为轻量驱动式 DCF。它负责：

- 固化历史收入基期和关键经营驱动；
- 管理悲观、基准、乐观三种预测情景；
- 计算 NOPAT、D&A、CapEx、营运资本变化与 UFCF；
- 使用 WACC 和永续增长法计算企业价值；
- 完成企业价值、净债务、股权价值和稀释每股价值桥接；
- 生成以当前假设为中心的 5×5 WACC × 终值增长敏感性矩阵；
- 保留 Evidence Ledger 来源、截至日期、审计结果和数据缺口。

本 Mod 不是完整三表模型、正式估值意见、评级系统或交易建议。完整三表、Excel 交付和复杂分部估值应由 Newma Agent 在用户明确要求后作为独立交付生成。

## 2. 数据分层

运行时必须明确区分：

1. 历史事实：财报、附注、行情或 Evidence Ledger 中已披露的数据；
2. 研究假设：增长、利润率、税率、资本强度、WACC 和终值增长；
3. 模型计算：收入、EBIT、NOPAT、UFCF、现值、终值与每股价值；
4. 数据缺口：无法从统一接口读取或仍需人工核验的字段。

缺失输入必须显示为缺失或审计失败，不得使用模型记忆或无来源估算静默补齐。

## 3. 最小模型结构

### 历史基期

- 报告期；
- 收入；
- EBIT 率；
- D&A / 收入；
- CapEx / 收入；
- ΔNWC / Δ收入；
- 对应 Evidence ID。

### 资本结构

- 当前股价；
- 稀释股数；
- 总债务；
- 现金及等价物；
- 无风险利率；
- Beta；
- 权益风险溢价；
- 税前债务成本与税率。

### 三情景驱动

每个情景必须按预测年度横向展示：

- 收入增长；
- EBIT 率；
- 税率；
- D&A / 收入；
- CapEx / 收入；
- ΔNWC / Δ收入；
- 情景 WACC；
- 终值增长；
- 情景依据。

## 4. 计算规则

```text
Revenue(t) = Revenue(t-1) × (1 + Growth(t))
EBIT(t) = Revenue(t) × EBIT Margin(t)
NOPAT(t) = EBIT(t) - max(EBIT(t) × Tax Rate(t), 0)
UFCF(t) = NOPAT(t) + D&A(t) - CapEx(t) - ΔNWC(t)
Discount Factor(t) = 1 / (1 + WACC)^(t - 0.5)
Terminal Value = Final UFCF × (1 + g) / (WACC - g)
Equity Value = Enterprise Value - (Debt - Cash)
Implied Price = Equity Value / Diluted Shares
```

约束：

- `terminalGrowthPct < waccPct`；
- 使用年中折现；
- 终值增长敏感性和 WACC 敏感性均使用 5 个对称取值；
- 中心格必须等于当前情景模型输出；
- 净现金使用负净债务表示并增加股权价值；
- 稀释股数、债务、现金或基期收入缺失时，不得输出伪精确每股价值。

## 5. 审计规则

页面至少显示：

- 历史收入基期是否存在；
- 历史输入是否关联来源；
- 终值增长是否低于 WACC；
- EV 到股权价值桥接是否完整；
- 终值现值占企业价值比例；
- 悲观、基准、乐观的末期 UFCF 层级是否合理。

终值现值占企业价值超过 75% 时显示警示，但不自动禁止保存，因为高增长公司和较短显式预测期可能出现该结果。

## 6. Newma Agent Context

Agent 可读取：

- 当前公司、情景、币种、单位和截至日期；
- 历史输入和资本结构输入；
- 三情景逐年驱动；
- FCF 预测与价值桥接；
- 5×5 敏感性矩阵；
- 审计检查、来源和数据缺口。

Agent 默认问题组：

- 假设与口径；
- 估值与敏感性；
- 审计与更新。

Agent 可以补充更长周期财务、财报附注、管理层指引、同业数据和宏观利率，但不得把模型输出直接转换为买卖或仓位建议。

## 8. 财报接入首轮（2026-09-20）

- 在“从已保存财报接入”中读取当前用户、当前工作区的财报底稿，预览后新建独立估值草稿，不改原财报或旧模型。
- `GET /api/research-archive/earnings-inputs` 提供收入指标及其引用证据（资本参考扩展见第 10 节），不复制经营讨论或其他研究正文。接口必须指定用户及工作区；损坏底稿返回错误，不回退其他工作区。
- 首版只接入人民币、完整年度、期间一致且已由用户采用原文证据的营业收入。亿元乘 100、万元除 100、元除 1,000,000，统一到百万元；不自动年化、不换汇。
- 保存上游底稿 ID、保存时间、原始收入单位和来源页码链接。手改收入或期间后撤下历史行来源关联，保留来源档案供核对。
- 预测年份从财报期末下一年开始；估值仍为基期末模型，未自动滚动到今日。三情景是待确认模板，不是财报预测或公司指引。
- 不用净利润代替 EBIT，不用经营现金流代替 UFCF，不用市值÷股价代替稀释股数。债务、现金、股数继续缺失，直至用户核验。
- “刷新股价”只采用证券、币种匹配的股价原值，不进行百万元换算，不改收入、基期、身份、股数、增长假设。读取期间如有编辑，不覆盖草稿。
- 金额单位固定；存量非百万元模型保留原标签并暂停计算。债务和现金须非负，股数须为正；净现金正确增加股权价值。WACC 权重目前以录入债务及股价×稀释股数近似，不是已核验市场价值权重。
- 本地估值缓存按用户和工作区隔离；保存明确区分 Desk 成功、本机浏览器保存和完全失败。旧全局缓存不自动带入其他工作区，未删除。

验收：核心计算及财报证据单测、研究档案接口工作区隔离、真实茅台 2024 年报上传→保存→估值接入→重开、行情刷新保护。真实收入为 1,708.9915227634 亿元，即 170,899.15227634 百万元；验收行情为明确模拟数据，非实时价格。

尚未完成：其他币种/期间适配、资本结构完整归集和独立核验、组织级预测假设审批、滚动估值时点及完整三表模型。本轮不宣称可直接形成正式投资估值意见。

## 9. 资本依据与情景人工确认（2026-09-20）

- 三项资本输入可记录来源标题/链接、页码或附注、原文摘录、单位换算和调整说明。股数区分期末/加权平均/稀释口径；有息债务不等于负债合计；现金须解释受限、客户资金等不可归属项目。零债务也需依据。
- 这是用户手工关联依据，不自动下载或验证链接，不自动确认摘录真实性，不是全文审计。原始上传年报仍走现有财报模块，本轮未新建 PDF 抽取器。
- `capitalEvidence` 保存三项输入的原文、说明、确认时间及当时证券/币种/基期/数值快照；`scenarios[].review` 保存逐情景确认时间与基期/驱动快照。均为可读输入快照，不使用哈希。旧模型保留数据，缺少新字段时视为待确认。
- 当前资本三项和当前情景均确认后，才输出每股试算及每股敏感性矩阵；价格差异还需同日股价，见第 10 节。确认前仍可看明确标注的现金流和价值桥接试算。数值可计算不等于证据已核验。
- 情景依据不能直接保留默认模板。基期、收入、预测参数或依据变化后需重新确认；资本数值、币种、证券或基期变化后旧资本确认失效。其他情景不得继承确认，行情价格变化不替用户修改研究假设。
- 首个预测年度须为历史基期下一年，估值时点须与基期末一致。“按历史基期对齐预测年度”只修改日期和预测年份，不改增速、利润率等数值，并撤销情景确认。
- 确认状态与人工依据进入统一页面上下文；Agent 预设问题先检查 `reviewStatus`，不绕过待确认状态补算每股价值或填造敏感性矩阵。
- 依据撤销保留资本数值和来源档案，不删除用户数据。所有确认先进入草稿，仍须点保存。

验收覆盖：确认缺失时停止每股输出、零债务依据、基期/数值/假设变更失效、确认跨保存重开、旧模型兼容、逐情景切换、撤销保存，以及上一轮真实年报接入回归。资本确认流程使用明确标注的模拟数据，不代表已核验茅台的股数、债务或可归属现金。

参考：复用本地 DCF 建模技能的输入溯源与分步确认原则，并核查 [Anthropic financial-services DCF 技能入口](https://github.com/anthropics/financial-services/tree/main/plugins/vertical-plugins/financial-analysis/skills/dcf-model)。未引入其 Excel 依赖，也未采用净债务作为 WACC 债务权重的示例。

## 10. 财报资本参考复用与时点修复（2026-09-20）

- 财报研究增加“补充资本项目”，从已上传 PDF 按需定位合并资产负债表；保存原始项目、金额单位、页码、表头、原文与报告 ID，不在估值侧重复解析。当前仅支持可可靠识别的人民币 A 股文字版年报。
- 跨模块接口仅增加资本事实白名单及其引用证据；仍按当前用户和工作区读取，不把其他经营指标和讨论正文一并复制。
- 资本核验面板可读取同证券、币种、年度基期且数值仍与原文匹配的已保存事实。“引用原文”保留上游底稿 ID/保存时间，填入摘录与物理页，不改资本数值、不自动生成调整方法、不自动确认。原文栏支持追加债务分项，避免重复引用；编辑资本数值保留已写的原文但撤销勾选确认。
- 股本仍是金额，不转成稀释股数；货币资金、客户存款分别展示，不自动相减得到可归属现金；一年内到期负债与租赁负债仍需核对附注和范围。借款空白不填零，负债合计不作为债务。
- `currentPriceAsOf` 随价格保存、进入 Agent 上下文。手改股价清除旧行情来源和日期；旧模型无股价日期或与估值基期不同，不显示 `impliedReturnPct`，明确说明未滚动至行情日。每股价值与股价比较是两道独立门槛，Agent 不得绕过日期门槛计算上涨空间。
- 手录新草稿先填收入后仍可补齐证券身份；绑定来源或保存模型后保持身份保护。历史年度标签和日期统一排序，同基期不同收入冲突时暂停预测，避免数组顺序决定结果。

后续优先级：先补资本附注调整、非经营性资产及少数股东权益桥接，再研究滚动估值时点和更多年报版式。当前版本仍是有来源、有人工确认的轻量研究模型，不是完整三表或自动投资意见。

## 11. 普通股价值桥接与现金口径（2026-09-21）

公式扩展为：经营 EV − 有息债务 + 可用现金 + 非经营性资产价值 − 少数股东权益价值 − 其他优先权益。

- 现金区分 `adjusted`（已经调整后的可用净额）和 `gross`（原始余额减 `excludedCashM`）。剔除额只能用于原始余额口径，须非负且不超过余额；切换口径保留原金额、摘录和说明，撤销现金相关确认，不自动转换金额。非适用模式下保留的旧剔除额不参与计算。
- 新增 `nonOperatingAssetsM`、`minorityInterestM`、`otherClaimsM`，均按百万元输入且默认缺失。普通股股权价值和每股值不再把缺失调整当零；确实不适用时须填零并给出依据。旧模型保留原数据，新增字段缺失时需要补充确认，不能继续沿用旧每股结果。
- 复用逐项资本来源核验，不增加另一套证据库或 Agent 内核。调整项均记录原文、定位、计算方法及数值快照；数值变化后确认失效。可用现金、调整净额、逐项桥接、确认状态和防重复计量规则进入 Agent 上下文与预设问题。
- 非经营资产只加回未纳入经营预测、未含于现金的估值；少数股东权益必须匹配合并经营现金流范围，不能自动以账面值替代；其他优先索偿不得与债务、现金扣减或稀释股数重复计入。全部金额仍由研究者核验，不是自动识别或公允价值审计。
- 默认净额模式需要六项资本依据；原始余额模式再增加剔除额依据。现金流与 EV 仍可试算，全部适用资本项目及当前情景确认后才显示每股值和敏感性矩阵；股价比较仍需同日数据。

参考：[Wall Street Prep 企业价值与股权价值](https://www.wallstreetprep.com/knowledge/enterprise-value/) 对优先股及少数股东索偿的处理。GitHub 的 Anthropic DCF 模板仍采用简化净债务桥接，本轮只借鉴分步溯源，不照搬其简化公式或增加 Excel 依赖。

边界：尚未自动提取受限资金附注、逐笔债务或对少数权益/非经营资产独立估值；也未实现滚动至今日的 DCF。本轮首先落实计算、口径选择、证据和保存闭环。

验收：47 项核心单测、3 项合同测试、1 项 Agent 问题测试、3 项页面测试及构建通过。覆盖缺失/负数调整、剔除额超余额、净额不重复扣减、模式切换撤销确认但保留原文、调整项持久化、旧模型缺项不填零，以及真实茅台年报引用回归。新增资本调整测试使用明确模拟数据，不是对茅台调整项的真实估值，也未调用模型生成投资结论。

## 12. 资本附注证据闭环（2026-09-21）

- 财报研究新增“定位资本附注”，复用已上传 PDF 与 pypdf，不新增文档服务或解析依赖。`earnings-candidates?notes=true` 按需扫描，默认上传仍仅提取前 30 页。
- 仅检索前 200 页内明确标注的合并财务报表项目注释；在下一财务附注章节终止。按附注标题和物理页分段，保留说明、单位和表头；最多 24 段，每段 6000 字符、总计 36000 字符，截断及遗漏明确提示。当前覆盖人民币 A 股文字版年报的部分版式，不支持 OCR，不声称查全所有披露。
- 用户展开、勾选、确认后新增 `sourceMaterials.capitalNote`，保存报告 ID、附注标题、原文、物理页、扫描范围和确认时间。不会覆盖财务指标、经营讨论或研究判断。同一报告同一附注同一页不重复添加；同页不同附注分别保存。
- 当前用户及工作区的已保存附注通过 `earnings-inputs` 提供给估值。估值端只列同证券、同币种、同年度基期且可用的参考，普通经营讨论仍不复制。
- 估值核验区展开附注后，可复制连续原文至摘录框；确认内容确实来自该段后追加上游底稿 ID、保存时间和物理页。不会自动截断超长引用、改数值、生成调整方法或勾选确认。依据仍需手工核验，采用后保存。
- Agent 财报上下文包含已采用附注及防重计规则；估值上下文沿用 `capitalEvidence` 已关联摘录，不声称读取未保存或未引用的全文。

真实验收：茅台 2024 年报物理第 106 页的“一年内到期非流动负债”和“租赁负债”分开定位，第 117 页保留现金构成及“不属于现金及现金等价物的货币资金”。后者不能从现金等价物余额中再次扣除；本轮不自动汇总债务或算出可用现金。

验证：48 项核心单测、14 项 PDF 提取测试、3 项工作区接口测试、6 项合同测试、2 项页面端到端测试通过，前端构建通过。真实 PDF 原页与界面截图均目视核对。页面验收包括勾选保存、刷新重开、跨模块引用、拒绝改写原文及保持资本数值缺失；没有调用真实模型生成投资结论。

研究取舍：复用现有 pypdf 文本提取和底稿存储。本轮追加查询 pdfplumber GitHub 文档超时，未将其视为已核查的迁移依据，也未新增依赖。

## 13. 资本调整明细（2026-09-22）

- 在“资本来源核验”的有息债务、现金及口径、需剔除现金中，可选择“使用明细合计替代手录数值”。每项记录项目、金额（百万元）、处理方式、文件/页码/附注和处理理由，共用本次来源标题、链接、原文摘录及计算说明；不另建证据库。
- 支持 1–12 行：`add` 纳入相加，`deduct` 只从已包含金额中扣除，`exclude` 仅保留观察记录、不加不减。表内显示合计和与当前值的差额。缺失、负数、定位或理由缺失时不允许采用；零债务需要显式零值纳入行及来源，不从空表推断零。合计按百万元保留 8 位小数（人民币分）。
- 原始余额模式下，现金明细不允许扣除，统一到“需剔除现金”归集；净额模式支持从已纳入余额扣除。剔除额不得超过原始余额。合计行与组成项、现金剔除与债务扣减的范围仍由研究者核验，系统不宣称自动识别所有重复项。
- 只有“确认采用明细及依据”才一次性替换当前数值和人工依据，然后需保存模型。未采用的编辑不改变当前模型，也不进入 Agent 上下文；取消编辑保留旧数据。取消明细方式后以手录确认会解除原明细关联，界面明确提示。
- 采用的明细随 `capitalEvidence.lineItems` 保存和重开，并进入 Agent 上下文。修改数值、证券、币种、时点、现金模式或明细内容后，旧确认不得沿用；即使改变理由/定位后合计未变，也须重新确认。已保存的坏行不能被静默丢掉后仅以剩余部分放行。
- 同步修复统一估值合同与实际计算结果不一致：预测结果允许保留税率、折旧摊销率、资本开支率和营运资本增量率；对旧结果保持可选兼容。

参考：核查 [Anthropic financial-services DCF 技能](https://github.com/anthropics/financial-services/tree/main/plugins/vertical-plugins/financial-analysis/skills/dcf-model) 的逐输入标注来源、分步确认及企业价值到股权价值桥接原则。本轮仅复用这些设计原则，保持现有前端计算、底稿保存及人工确认，不新增 Excel 引擎或其他依赖。

验收：52 项核心测试、3 项合同测试、3 项页面端到端测试及前端构建通过。包括明细符号、缺失不当零、现金模式防重复扣减、确认后替换、保存重开、取消不覆盖、总数与明细冲突提示、Agent 上下文和原有真实年报引用回归。新增明细采用明确模拟数据（100+40-10=130，另 70 仅记录），不代表已核验茅台真实资本结构；没有调用真实模型生成投资结论。

## 14. 未核验编辑暂存与嵌入确认（2026-09-23）

- 资本来源编辑增加“暂存未核验编辑”：复用模型保存入口，一并保存当前模型及 `capitalEvidenceDrafts`，允许金额、原文、理由尚未填写完整。存储目的地仍明确区分 Desk 工作区、本机浏览器和保存失败；不是自动保存，用户须主动点击。
- 暂存不修改 `capitalInputs`、已采用的 `capitalEvidence` 或人工确认；计算只用已采用数据。恢复时标记未核验，金额/证券/币种/基期/现金模式与暂存时不同则提醒复核，不自动换算。核验采用后清除该项暂存，其他资本项目暂存保留。
- 用户可放弃该项暂存，页面内二次确认后保存，已采用数值及原证据不被删除。暂存中的输入也会阻止跨模块证券事件悄悄替换模型身份。
- Agent 页面上下文只增加待核验字段与保存时间提示，不把暂存明细列为已确认来源，也不把暂存合计参与估值。打开编辑框后继续修改但未暂存的内容仍只存在于编辑器内。
- 验收发现嵌入 iframe 未开放 `allow-modals`，浏览器 `confirm()` 被拒绝。未放宽 iframe 权限；改用页面内二次确认，并将估值页新建、切换、删除、从财报接入的同类确认改为 HTML dialog。取消保留当前内容，删除前明确不可撤销及暂存一起移除。

参考：[React 保留和重置状态](https://react.dev/learn/preserving-and-resetting-state) 提醒组件内状态随卸载消失。本轮把需长期保留的编辑提升到现有模型存储，仍区分草稿与采用状态，不新增存储服务或依赖。

验证：54 项核心测试、3 项合同测试、4 项页面测试及构建通过。覆盖不完整明细保存重开、暂存不改变估值/确认、采用后清理、放弃暂存、时点口径变更提示，以及 iframe 内新建/切换/删除/财报接入的确认和取消。新增金额使用模拟数据，真实年报仅做原文引用回归；未调用真实模型生成投资结论。

## 15. 未暂存编辑保护（2026-09-24）

- 资本编辑器的来源、原文、口径及明细改动单独标记“未暂存”。在估值页内切换核验项目、取消编辑、新建或切换模型、从财报新建时，用现有页面确认框提示是否放弃。取消操作保留输入，明确放弃只丢弃本次未暂存改动；已暂存及已采用内容不受影响。仅打开编辑器或把输入改回原值，不产生额外确认。
- 修复编辑器把证券、基期及现金口径作为组件 key 导致输入随变化丢失的问题。现在保留原文和明细，清除核验勾选及旧参考列表，并要求重新核对适用范围；旧范围的异步参考不回填新范围。
- 从原始现金余额切到已调整净额时，正在编辑的“需剔除现金”仍保留，可暂存，但不能采用。切回原始余额后可恢复核验，不做自动换算或重复剔除。
- 顶部“保存”发现未暂存的资本编辑时，明确要求先暂存或采用，不再只保存模型却让人误认为编辑也已保存。暂存期间禁用编辑区，避免保存完成关闭时丢失途中新增内容。未暂存编辑也阻止跨模块证券选择事件替换身份。
- 边界：本轮保护估值页内操作，不拦截 Desk 切换其他模块、浏览器刷新/关闭；离开前仍需主动暂存。没有新增自动保存或离线/远端冲突合并。

参考：核查 [React 保留和重置状态](https://react.dev/learn/preserving-and-resetting-state) 对 key 与组件状态生命周期的说明；复用已有确认框和模型存储，不新增依赖。

验收：54 项核心测试、3 项合同测试、5 项页面测试及构建通过。新增页面验收覆盖模型本身未改动时的未暂存提示、确认/取消、恢复原值不误报、重开同一模型清理已放弃编辑、切换核验项、变更基期/现金口径保留空金额明细、暂存后刷新恢复。真实年报引用回归也显式确认放弃未暂存摘录；新增资本输入均为模拟数据，没有生成投资结论。
