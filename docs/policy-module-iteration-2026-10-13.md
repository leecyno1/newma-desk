# 政策栏目三轮迭代 · 2026-10-13

范围：政策渠道、政策流、政策日历、政策解读。仅本地运行；不改持仓、交易或基金共享库，不部署、不自动推送 Git。

## 第一轮：官方正文和证据口径

- 官方 HTML 正文读取、保存和重新抓取；明确正文区域，排除导航、脚本和页脚。未识别正文、仅 PDF 附件、无法访问均明确报错，不以摘要替代。
- 保留发文机关、文号、网页发布日期、成文日期、明确施行条款和采集时间。没有施行日不默认已生效，未来施行日不标记当前已生效。
- SQLite 保存正文记录，文字或关键元信息改变时保留新记录；获取失败保留旧正文。
- 政策量级判断从事实栏移出；降低“行业规划 + 引用国务院”导致的虚假战略级判断。人工确认不被重新采集覆盖。
- 页面生成时间与来源采集时间分开，渠道异常/旧缓存不会因为刚打开页面就变成 fresh。

## 第二轮：投资研究底稿

- 支持直接导入官方政策正文 URL，并复用已有官方 URL 的政策身份。
- 同一官方页面的新旧正文、或更早同系列正式文件可作文字对照。摘要仅作关键词参考；不把未来文件拿作历史基准。
- 同系列关系未经人工确认，明确标为参考，不宣称正式修订/废止。只有一份正文、正文截断时不给全文差异结论。
- 利率、财政、资本市场、科技、绿色转型、外贸六类传导研究模板：每条引用正文段落，提供验证指标和失效条件，统一标记待复核。
- 模板不估算收益、仓位或安全垫，不宣称当前组合已经受影响，不自动向风险模块生成告警。
- 研究底稿可导出 JSON，包含政策身份、正文记录、官方来源、方法版本及未复核状态。正文持久化不等于 AI 回答、研究底稿已纳入统一研究档案。
- 底稿生成不调用模型；“问 Agent”是单独操作，使用 Desk 已配置的 Newma/CLI/Copilot，不强制依赖 Newma。

## 第三轮：采集与使用验收

- 中国政府网 RSSHub 失败时可回退官方政策目录 JSON；这里只发现标题和日期，不能视为已经读取正文。
- 独立页与四个 Desk 入口使用同一份数据；移除重复页面标题，条款依据折叠，先展示传导和验证内容。
- Agent 上下文包含当前正文、底稿、来源状态和正文读取错误，不重复发送正文，也不把尚未生成的报告列成可见数据。
- 读取失败/切换政策不会把上一个政策的正文或错误传给当前对象；较慢的旧 GET 不能覆盖刚抓取的新正文。

## 实际验收

编译通过；政策后端 27 项测试、浏览器 4 项测试通过。浏览器覆盖真实政策导入、导出、正文持久化重新读取、失败保留旧记录、对象切换、独立入口和四个 Desk 入口。没有把这视为模型分析质量或全系统投资业务验收。

## 外部参考与采纳

- [RSSHub](https://github.com/DIYgod/RSSHub)：保留现有采集层。本次实查静态列表路由可能漏动态列表；采用中国政府网官方目录 JSON 回退，不复制上游代码。
- [changedetection.io](https://github.com/dgtlmoon/changedetection.io)：借鉴正文筛选、保存快照、变化定位；未引入独立服务。
- [Trafilatura](https://trafilatura.readthedocs.io/en/latest/usage-python.html)：评估过通用正文提取，但不能直接解决政策四类日期的语义差异；本轮不采用。
- API 新增轻量 beautifulsoup4 依赖及锁定记录，复用现有 httpx。没有添加浏览器爬取服务。
- 政策监测技能要求一手来源、事实/推断/不确定性分层，已落实到数据和界面。
