# Newma-Desk 投资体系能力地图

更新日期：2026-08-18

当前官方商店共 95 个 Mod，归入 16 个一级模块。一级模块表达长期投资能力边界，不按来源仓库、运行端口或技术框架分类；同一运行时可以通过不同 Suite 复用，但同一页面只能有一个主归属。

## 1. 能力边界与现状

| 一级模块 | 核心问题 | 当前 Mod | 当前判断 |
| --- | --- | --- | --- |
| 全球 | 全球发生了什么，哪些事件可能跨市场传导 | 全球情报、联储加息、美伊战争、中美贸易、新闻与舆情、催化剂日历 | 地图、新闻和专题框架已形成；专题历史库、情景概率和资产传导仍需统一 |
| 宏观 | 经济处于什么阶段，未来增长、通胀和金融条件如何变化 | 宏观观察、周期叠加 | 模块偏弱；缺少经济意外、领先指标、预测修正和跨资产验证 |
| 政策 | 哪些政策将发布、已发布什么、量级和影响是什么 | 政策渠道、政策日历、政策流、政策解读 | 页面已拆清；下一步是统一政策身份、版本差异和真实来源覆盖 |
| 资金 | 钱从哪里来、流向哪里、是否形成持续增量 | 个股资金、资金总览、跨境资金、流动性、ETF 资金、资金风险偏好 | 数量、价格与市场传导已分组接入；ETF 申赎和部分历史基线仍待补齐 |
| 市场 | 市场现在如何交易，价格、宽度和结构发生了什么 | 行情、大盘云图、市场情绪、技术分析、多周期分析、强弱对比、日线时间轴、市场复盘、缠论结构分析 | 行情、复盘和结构分析边界已拆开；需统一证券主数据、交易日和复权口径 |

| 创作 | 投研成果如何转成内容并发布、复盘 | 状态看板、内容采集、选题 Brief、初稿生产、多通路转写、发布、复盘、超市项目、项目设置 | 六阶段工作流已建立；保持与投资决策账本隔离，只引用已发布研究 |

## 2. 已确定的去重规则

| 易重复能力 | 统一处理 |
| --- | --- |
| 资金风险偏好与市场情绪 | 市场保留涨跌家数、涨跌停和宽度；资金只看行业资金、北向/南向、流动性和成交驱动，不复用涨跌停接口，不生成虚假综合分数 |
| 行情与市场复盘 | 行情负责实时查看；市场复盘负责收盘后的结构、异动和归因 |
| 催化剂日历与日线时间轴 | 催化剂日历负责未来事件和验证条件；日线时间轴负责已发生事件与价格对齐 |
| 公司事件、个股资金 | 公司模块负责围绕研究对象组织证据；资金模块负责资金口径下钻，通过 Wiki 跳转而不复制数据 |
| 行业轮动与资金总览 | 资金总览只显示市场级资金摘要；行业模块承载行业排名、轮动和产业链解释 |
| 研究机会、综合选股、策略筛选、自选股 | 保留不同入口，但最终写入同一候选账本；不再各自维护不可互通的名单 |
| 配置、风险与交易 | 共享一个 Portfolio Ledger；配置决定目标，风险约束目标，交易记录执行，页面不互相复制持仓 |
| 项目设置与栏目数据能力 | 业务参数留在 Mod；Desk 的 Provider、权限、Agent 和栏目接入统一放在二级面板底部“栏目数据与能力” |

## 3. 优先补足

### P0：下一版本必须完成

1. **统一证券主数据**：覆盖全部 A 股、ETF、开放式基金，统一市场、代码、名称、上市状态、交易日、复权和公司行动；所有 Mod 只引用 Canonical ID。
2. **风险中心实装**：补组合集中度、行业/风格暴露、相关性、最大回撤、压力场景、风险贡献和预警；直接读取 Portfolio Ledger。
3. **资金历史底座**：保存行业、北向/南向、ETF 份额、全市场两融和成交快照，提供 1/5/20 日变化与来源新鲜度，不混加不同口径。
4. **政策统一账本**：政策日历、政策流和政策解读共用政策 ID、发布机构、生命周期、原文版本和逐字差异，AI 结论必须回指原文证据。
5. **Wiki 覆盖扩展**：当前只有 13/95 个 Mod 声明 Wiki Profile。优先覆盖市场、行业、公司、基金、策略、配置和风险主链，统一标的与研究意图跳转。

### P1：形成完整投研闭环

1. 宏观增加经济意外指数、增长/通胀 Nowcast、收益率曲线、信用条件和预测修正。
2. 行业建立申万 31 个一级行业与二级行业主表，接入景气、盈利预测修正、估值分位和产业链证据。
3. 公司补一致预期、三表模型、估值历史、股东与公司行动，并让结论进入 Evidence Ledger。
4. 基金补持仓穿透、风格漂移、跟踪误差、费率、经理任职和同类基准。
5. 策略建立 Candidate Ledger，统一来源、规则、入池日期、证伪条件、复核日和研究交接。
6. 交易建立“计划 -> 纸面执行 -> 成交质量 -> 复盘”的闭环；真实券商执行继续保持关闭。
7. 投决只消费已版本化的研究、配置和风险产物，记录决策、反方意见、失效条件和复核日期。

### P2：扩展资产与高级能力

1. 在现有模块内补债券、信用、商品、外汇、期权和海外基金研究，不新增一级栏目。
2. 建立跨资产情景引擎和组合级流动性压力测试。
3. 预测模型统一进入样本外验证和漂移监控，通过后才可展示为研究信号。
4. Deepsee 与创作只通过标准研究引用回写反馈，不反向修改投资事实账本。

## 4. 下一阶段实施顺序

`证券主数据 -> Portfolio Ledger 与风险中心 -> 政策/资金历史账本 -> Wiki 主链覆盖 -> 宏观与行业深化 -> Candidate Ledger -> 交易与投决闭环`

这个顺序先修公共数据和事实账本，再扩展页面能力。否则新增 Mod 仍会重复取数、重复维护标的，并继续产生同名但不同口径的结果。
