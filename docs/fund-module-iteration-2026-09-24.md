## 已有能力与具体断点

### 1. 研究能力可复用

`FundResearchSnapshotService` 已整合分类、同类评价、持有体验、回撤修复、经理历史、规模变化和风格漂移等服务。份额服务已有产品实体、A/C 份额及费用区分。当前不宜再增加一个独立评分引擎。

### 2. Agent 结构化上下文不代表实际数据

初查时，`lib/newma-desk/context.ts` 的 `buildFundResearchPageContext` 主要输出功能列表，未传日期时取当前时间，并固定 `freshness: fresh`。调用处只传工作区和选择对象，没有传页面实际基金数据、筛选条件与证据日期。本轮已移除虚构的新鲜度与默认日期，列表和详情改为传实际页面数据，其他工作区暂明确标注为功能说明。

Desk 即使另有页面文本回退，也不能用它抵消结构化元数据的错误。应让上下文使用真实页面事实，区分渲染时间、净值日期、持仓报告期和披露日；没有数据时为 unknown/缺失，不声称“最新”。

### 3. 现有基金组合是研究组合，不是实盘账户

`PortfolioService.check_admission` 会以滚动指标是否齐备作为候选准入条件；`_effective_weights` 在权重不齐时按等权聚合。这适用于披露假设的研究模拟，不适用于接收用户实际持有、但尚无研究覆盖的基金。

实盘账户继续归组合中心：未识别或证据不足的基金必须保留，并计入未知覆盖；不拒绝真实持仓，不擅自改成等权。基金模块从组合中心读取当前用户/工作区授权的基金持仓，不另维护一份市值账本。

### 4. 风控读取的基金证据范围过窄

`backend/routes/newma_desk.py` 的 `fund_risk_evidence` 当前只投影本地久期估计；组合中心 `evidence.py` 也只接收该类参考。需扩展为基金身份、净值及风险摘要、披露持仓和覆盖缺口，继续保持只读，不因访问风险页触发抓取或 AI。

### 5. 重仓相似度不等于账户风险敞口

已有 `FundHoldingSimilarityService` 只比较同报告期前十大公开重仓股，分别归一化后计算相似度。该定义有合理研究用途，应保留，但不能把归一化结果当作基金净资产中的实际权重。

持仓风险投影应使用原始权重及分母：基金净资产占比可直接用于已披露敞口；股票仓位内部占比必须同时具备股票仓位比例才能换算。其余部分标记未知。未来与直持股票合并时，以账户持有基金市值乘以底层净资产占比计算已知间接敞口，避免把基金本体和穿透明细重复加总。

## 建议实施顺序

1. **连接修复**：先修 Agent 上下文的数据内容、新鲜度和筛选一致性；逐项核对嵌入页面跳转是否保持 Desk 适配。独立运行保留原行为。
2. **持有基金视图**：从组合中心读取真实基金持仓，保留账户/产品身份与份额代码；同一基金不同份额可汇总风险，费用和净值仍按份额区分。缺数据不阻止显示。
3. **证据输出**：复用现有研究快照、持仓和份额服务，补齐只读风险证据。显示数据日期、来源、覆盖与缺项；不增加新的研究/交易内核。
4. **已知重叠**：先支持基金之间已披露股票的交集及持仓贡献，再与组合中心直持股票联调。前十大相似度和真实净资产敞口分开展示，不以缺失推断零风险。

首轮不做全市场重新抓取、自动买卖、优化器扩展或完整 FOF 多层穿透。真实数据同步如需调用有额度的数据源，另定基金清单和更新范围。

## 验收标准

- 手选基金、筛选列表、切换份额后，Agent 所读对象和页面一致；缺日期数据不能标记最新。
- 持仓中存在未覆盖基金时，数量和市值不丢失，显示未知覆盖而非低风险。
- A/C 份额归属同一产品时避免虚增分散度，但不混用净值和费率。
- 披露只有前十大时，不补齐为 100%；股票仓位占比与基金净资产占比不混用。
- 持仓报告期、公告日与分析时点可追溯；历史评估不使用事后披露的证据。
- 挂载 Desk 与独立基金应用分别验收，不修改独立应用端口、数据库和业务规则。
